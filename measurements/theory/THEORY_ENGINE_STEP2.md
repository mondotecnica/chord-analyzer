# Theory Engine 第2段: 最小の系列再評価器 — 実装と測定

作成日: 2026-10-29（§1〜§3 は測定実施前に書いた事前登録であり、
§4 以降の結果はその基準に対する判定である）
位置づけ: THEORY_ENGINE_DESIGN.md §7 の第2段。認識エンジン本体は
無変更で、第1段の候補列を消費する純粋な後段モジュール
（src/analysis/theoryReevaluation.ts）を両経路へ明示オプトイン
（`theoryReevaluation`、既定 OFF）で接続した。製品既定は変えて
いない。数値の一次資料: theory-step2-results.json（本ディレクトリ、
`npm run measure:theory-step2` で再生成可能）。

## 1. 実装内容

- 新モジュール `src/analysis/theoryReevaluation.ts`:
  セグメント系列に対する Viterbi 系列最適化。状態 = 各セグメントの
  候補（最大 k=5）＋ N.C. セグメントの N.C. 状態。出力は再評価済み
  セグメント列で、反転したセグメントにだけ根拠内訳
  （`ChordSegment.theoryRationale`: キー／ダイアトニック／遷移（前）
  ／遷移（次）の寄与差と音響マージン）を加算的に残す（設計書 §3）。
- 接続点: 混合音経路（analyze.ts）・ステム経路（analyzeStems.ts）
  ともに、第1段の候補露出の直後。文脈入力は記録済みの局所キー
  （結果の localKeys と同一内容。記録が無ければ全体キー）。
  第2段が有効な場合は候補列も結果に付く（評価器の入力であるため。
  candidateRecord 単独時の挙動は従来どおり）。
- 使う評価軸（設計書 §1 の 5 軸中 3 系統のみ）:
  (1) キー整合性: 候補構成音の局所キースケールへの fit
      （窓の次点キーは相関差に応じた重み ≤ 0.5 で加重平均）。
  (2) ダイアトニック整合性: 全体キーへの fit を「説明可能性」で
      浅くする — 二次ドミナント（V/x）・平行調からの借用・
      ナポリ和音は減点の床を fit 2/3 とし、説明のつかないもの
      だけが生の fit を受ける（§6.3）。短調の V は和声短音階の
      例外として fit 1。
  (4)(5) 機能的遷移: エッジ特徴として評価。規則は標準的な機能
      和声の定型（V→I +1.0、二次ドミナント解決 +0.9、プラガル
      +0.6、五度下行 +0.6、偽終止 +0.3、V への進行 +0.35、
      V→IV −0.5、V→ii −0.35、同一コード継続 +0.4 等。非ダイア
      トニック同士はルート運動だけの弱い評価に落とし、非ダイア
      トニックであること自体は遷移では罰しない＝二重罰の回避）。
- 含めないもの: (3) 進行統計（様式パック＝第3段）、拡張段の候補
  （maj9/maj13 の命名を含む）、ボイシング／楽器特徴。
- N.C. の扱い（§6.5）: N.C. セグメントは N.C. 状態のみを持ち、
  ラベルありセグメントにも N.C. 状態を置かない。理論はラベルを
  発明も消去もしない。N.C. に触れるエッジは中立（0）。
  したがって N.C. 時間は構成上不変であり、基準5で検証する。
- 反転の保護: extension／upperChord／addTones／ncFill が付いた
  セグメントは反転させない（装飾は旧コアに対して判定された
  もので、コアだけの差し替えは不整合になるため）。

### スコア合成と上限（§5 の具体化）

- 合成は対数線形: 状態スコア = emission ＋ 重み×（キー特徴 ＋
  ダイアトニック特徴）＋ エッジごとの 重み×遷移特徴。
- **emission の設計**: 候補スコア（コサイン）そのものではなく
  第1段の符号つきマージンを主信号にする（第1段引き継ぎの警告:
  スコアは較正済み確率ではない）。変換は順序保存の逓減型 —
  接戦域 |margin| ≤ E（= 0.06）では額面どおり、外側は 1/4 の
  重みで数える。根拠: 集計は上帯域だけの1視点であり、その強い
  言い分は逓減させるが、代替同士の順序（どの代替を集計が最も
  支持するか）は仲裁の材料として潰さない。正マージン側は
  下記のガードと合わせて「勝者が集計でも明確に優位な候補は
  覆らない」を保つ。負マージン側に硬い上限を置かないのは、
  その場合の反対者は理論ではなく集計自身（音響側の別視点）
  であり、理論の役割は代替同士の仲裁と上限内での勝者擁護に
  限られるため。
- **理論寄与の上限**: 特徴の値域と重みから、1 セグメントの
  理論優位（候補 − 勝者、両隣エッジ込み）の最大値が
  swingCap = w_key + w_dia + 4·w_tr = 0.06 で構成的に決まる。
  加えて後段ガードで、生マージン ≥ swingCap の候補への反転は
  経路全体の都合でも起こさない。タイブレーカーが原則であり、
  理論単独で覆せるのは接戦域だけである。

## 2. 較正の根拠（重みと上限を先に固定した理由）

重み・上限は評価対象スイートの正解を見ずに、設計原則と
第1段候補のマージン分布（真値なしプローブ、2026-10-29）だけ
から固定した。評価スイートでの最適化はしていない。

プローブで測った rank-2 候補マージンの分布（ラベルあり
セグメント、候補データのみ）:

| 対象 | p25 | 中央値 | p75 | p90 |
|---|---:|---:|---:|---:|
| 合成 A〜I 混合音 | +0.001 | +0.126 | +0.190 | +0.216 |
| 実曲 混合音 | −0.107 | −0.019 | +0.038 | +0.085 |
| 実曲 ステム | −0.136 | −0.007 | +0.060 | +0.113 |
| Suno 05 混合音 | −0.157 | −0.043 | +0.022 | +0.087 |
| Suno 05 ステム | −0.176 | −0.070 | +0.035 | +0.082 |

読み: 実曲では集計が勝者と割れている（負マージン）のが常態で、
「集計が曖昧」と言える幅はせいぜい ±0.06 程度。合成では典型的
な決着マージンが 0.13 前後ある。swingCap = 0.06 は、実曲の
曖昧幅の上限側かつ合成の決着マージンの半分以下に置いた。
配分は §6.7 の有望度（遷移は音響とほぼ独立）に従い、遷移 1/2
（w_tr = 0.0075、エッジ両側で最大 0.03）、キー整合性 1/4
（w_key = 0.015）、ダイアトニック 1/4（w_dia = 0.015）。
emission の接戦域 E は swingCap と同値 0.06、逓減率は 1/4。

実例の確認（較正ではなく設計の検証）: stems-05 の Q3 窓
（87.63–89.30 秒、勝者 A）の候補は B major がマージン −0.586 で
集計最有力。emission は逓減後も +0.19 あり、理論側は局所キー窓
（C major と読む窓）が B に僅かに不利でも上限 0.06 の範囲では
集計の言い分を覆せない — 「理論はタイブレーカー、集計の強い
反対は音響側の証拠として数える」という役割分担がこの形で
現れることを実装前に確認した。

### 4.3 切り分け（感度・探索変種と診断。合否には使わない）

敗因を分けるために、主構成の判定を確定させたうえで変種を
測った。

- **集計 argmax のみの精度（診断）**: 実曲では混合音 root
  25.5%／ステム root 30.5% と、パイプラインの top-1
  （32.2%／41.2%）を大きく下回る。上帯域集計は単独では
  勝者より弱い証拠であり、そこへ広く追従させる設計は
  実曲では構造的に負ける。
- **emission-flat（接戦域の外を完全にクランプ）**: 反転数は
  主構成とほぼ同一（実曲各スイートで一致〜±1）。つまり反転の
  大半は接戦域の内側（|margin| ≤ 0.06）ですでに決まっており、
  逓減尾は主因ではない。実曲 triad は混合音 18.9%／ステム
  30.3% と主構成以下〜同等で、なお不合格水準。
- **emission-floored（負マージンを emission 0 に切り捨て）**:
  損害は約半分に減り（実曲 triad: 混合音 21.8%／ステム
  34.9%、Δ は −4.2／−3.4pt）、合成はプラスに転じた
  （root 88.1%＝Δ +1.3pt、triad 84.5%＝Δ +4.5pt）。B7 の
  回復（68.3%）も維持された。ただし実曲は依然マイナスで、
  Q3-Am は stems-05 で 70.7 → 31.7%、宵 B で 92.7 → 0.0% と
  なお壊れる。**結論: 最大の増幅器は「負マージン＝集計の
  支持」という emission の意味論だったが、それを直しても
  理論特徴そのものが実曲の接戦域で系統的に裏目に出る**
  （局所キー窓のノイズ、非機能的な実曲の動きへの遷移表の
  ミスマッチ、解決先コードの弱い擁護）。
- **軸の内訳**: transitions-only が合成 triad 84.3%（主構成
  80.7%）と最良で、遷移軸自体は合成では有効。nodes-only は
  実曲混合音 triad 18.4% と最悪で、キー／ダイアトニック項
  （とりわけ局所キー依存）が実曲で最も危ない。cap の
  ×0.5／×2 は結果をほとんど動かさない（上限は拘束として
  効いていない — 反転は上限よりずっと小さい優位で起きている）。

### 4.4 なぜ狙った場面では働いたか

Song D（+19.0pt）と B7（0 → 68.3%）はいずれも「集計が構造的
に正しく、フレーム／ベース側の都合で勝者が歪んだ」場面で
ある。そこでは集計への追従がそのまま修正になる。実曲の
大多数の接戦はその形ではなく、集計の代替は単なる別視点の
ノイズであり、勝者のフレーム列＋ベース証拠を emission が
表現できていない（勝者の身元以外の情報を持たない）ことが、
守りの弱さとして現れた。第1段の引き継ぎ（「スコアは較正
済み確率ではない」）を、設計は emission の逓減で処理した
つもりだったが、実測は「負マージンに正の支持を与えること
自体が誤り」という、より強い形で返ってきた。

### 4.5 回帰

全テスト合格（§4.1 基準5 の内訳どおり。単体テスト 11 件を
theoryReevaluation に追加し、反転の機構・上限・保護・N.C. の
扱いを固定した。測定テストは関門の合否パターンを記録として
固定している）。製品既定は不変（theoryReevaluation は明示
オプトインのまま）。

## 5. 第3段への引き継ぎ

- 本測定の結論は「第2段の主構成は不採用」であり、第3段
  （様式パックの進行統計）に進む前に、第2段の再設計が要る。
  再設計の出発点として実測が支持するのは次の3点:
  (1) emission は floored 意味論（負マージンに正の支持を
  与えない）を前提にする、(2) キー項は局所キー窓の信頼度
  （margin／相関）でゲートし、曖昧な窓では黙る形にする、
  (3) 遷移軸は合成で有効だった一方、実曲では「解決先の
  主和音を守る」項（終止の受け側の擁護）が不足しており、
  格上げだけでなく現ラベルの擁護として遷移を両方向で
  効かせる設計が要る。
- いずれも本測定の事前登録の範囲外であり、再挑戦する場合は
  改めて基準を登録してから測ること。特に emission の意味論
  変更は「設計の修正」であって、本結果の判定は変えない。
- 様式パック（第3段）・拡張段の候補露出・楽器同定の前提は
