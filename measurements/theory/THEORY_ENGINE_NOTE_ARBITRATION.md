# 音符仲裁を主軸にした再評価器: Theory Engine の再開と測定

作成日: 2026-10-29（§1〜§3 は測定実施前に書いた事前登録であり、
§4 以降の結果はその基準に対する判定である）
位置づけ: THEORY_ENGINE_STEP2_RETRY.md §5 の再開条件 (a)
「音符レベルの証拠が評価器の入力に加わること」が、
EVIDENCE_SELECTION.md の診断で実測充足された（選択済み音符
証拠の仲裁正解率 0.745、集計 0.357／現行勝者 0.643 を上回る）
ことを受けた再開作業。ただし再開するのは v1/v2 の「理論主軸」
ではなく、提言どおり**音符仲裁を主軸に置き、理論項は音符が
棄権した接戦での補助に回す**新しい消費者である
（src/analysis/noteArbitration.ts、オプション
`noteArbitration`、既定 OFF の明示オプトイン）。理論側の数値は
THEORY_WEIGHTS_V2 を凍結したまま使う。push なし、製品既定は
変えていない。数値の一次資料: theory-note-arbitration-results.json
（本ディレクトリ、`npm run measure:note-arbitration` で再生成可能）。

## 1. 設計

### 1.1 発火条件（作用範囲を構造で bound する）

- 対象はラベルあり・装飾なし（v1/v2 の反転保護を踏襲）の
  セグメントで、**挑戦者 = 候補列の2位（candidates[1]）の
  マージンが接戦帯 0.06 以内**にあるものだけ。それ以外には
  一切触らない。
- 第1段の候補列は「1位 = 確定ラベル、残りは集計スコア降順」の
  順序が保証されている。したがって集計 argmax は、2位の
  マージンが負なら2位そのもの、正なら勝者自身であり、
  「勝者と集計 argmax が割れている」ことと「2位が接戦帯に
  いる」ことは上記の1条件に帰着する。EVIDENCE_SELECTION の
  仲裁診断が対象にした母集団（割れた 507 件）はこの条件の
  部分集合（マージン < 0 の側）である。
- N.C. セグメントには触らない（ラベルを発明しない。N.C. の
  時間は構成上不変）。候補が2つ未満のセグメントも対象外。

### 1.2 主軸: 音符仲裁

- 証拠は noteEvidenceSelection の既定構成（持続重み＋メロディ
  分離、フォールバック契約つき）で、セグメント列全体に対して
  選択した選択済み和声証拠を使う（消費側で条件を変えない）。
- 挑戦者と現ラベルの三和音説明率（triadExplained）の差
  Δ = 説明率（挑戦者）− 説明率（現ラベル）が、事前登録した
  閾値 noteFlipDelta = 0.10 を**超えた**場合だけ反転する。
  Δ < −0.10（音符が現ラベルを明確に支持）なら現ラベルを
  維持する。これは EVIDENCE_SELECTION §2.2 の仲裁方法
  （説明率の大きい方に投じる）の形式化であり、閾値は診断の
  「同点は棄権」を「決め手になる差」へ厳しくしたもの。
- **棄権**は次の場合: (i) 証拠が無い（pcWeights が null）、
  (ii) 選択のフォールバックが発動した、(iii) 説明率が同点
  （Δ = 0）。棄権した接戦だけが理論段（§1.3）の対象になる。
- 音符が弱く発言した（0 < |Δ| ≤ 0.10）場合は現ラベルを維持し、
  **理論補助も重ねない**。主軸の閾値を補助で迂回しないため。

### 1.3 補助: 理論（凍結した v2 構成の pairwise 適用）

- 音符が棄権した接戦に限り、THEORY_WEIGHTS_V2（floored
  emission／キー項信頼度ゲート／現ラベル擁護 H = 0.005、
  重み・遷移表とも凍結）をタイブレーカーとして使う。
- 適用は v2 の Viterbi そのものではなく、**隣接ラベルを
  音符段の確定ラベルに固定した pairwise 評価**に制限する:
  挑戦者の優位 = emission（挑戦者マージン）＋ キー項差
  （ゲートで沈黙する窓では 0）＋ ダイアトニック項差 − H
  ＋ 前後の遷移差（隣が N.C. の辺は 0）。優位が厳密に正の
  場合だけ反転する。ノード／エッジの意味論と数値は v2 と
  同一であり、系列全体の再最適化をしない点だけが異なる
  （理論段の反転同士は互いを文脈として見ない。音符段の
  ラベル列で全て評価する）。
- 理論補助の寄与は、ablation（theoryAssist: false、合否には
  使わない）で分離して報告する。

### 1.4 否定保護（新設計）

- 格上げできるのは candidates[1] だけである。**3位以下の
  候補は、音符証拠がどれだけ強く支持しても単独では復活
  させない**。あわせて、2位でもマージンが接戦帯（0.06）を
  超える候補は対象外（発火条件と一体）。
- Q2 の Cm がこの設計で構造的に防がれることの検証
  （§2 の窓ダンプによる。決着済みフィクスチャの設計検証で
  あり、閾値の調整には使っていない）:
  - stems-05 の Q2 窓で現ラベルが Am のセグメント
    （157.48–158.31 秒、158.31–159.52 秒）では、Cm は候補列の
    **4位**であり、集計 argmax は C である。Cm の音符説明率は
    0.35〜0.50 と無視できない水準にあるが、挑戦者の席
    （2位 = C）に着けないため格上げは起こらない。実際に
    2位 C への仲裁も、音符が現ラベル Am を支持して不発に
    終わる（Δ = −0.004／−0.19）。
  - 現ラベルが Cm 自身のセグメント（152.65–156.13 秒、
    165.65–167.32 秒。baseline 自身の読み）では、音符証拠は
    Cm を支持側に回るか（説明率 1.0、165.65–167.32 秒）、
    2位 G への反転が Cm の割合を減らす方向にだけ働く
    （152.65–156.13 秒、Δ = +0.117）。したがって Cm の
    ラベル時間割合は baseline を上回り得ない。
  - mixture-05 でも同型: Cm が現ラベルでないセグメントでは
    Cm は上位候補に現れず（165.70–166.81 秒の Cm は
    baseline 自身の読みで、音符は説明率 0.982 でそれを支持
    する）、増える経路が無い。

### 1.5 反転の規則と根拠内訳

- 反転はコアラベル（chord）のみ。bassPc・信頼度・境界・
  候補列は変えない。装飾つきセグメント（extension／
  upperChord／addTones／ncFill）は反転保護する（v1/v2 踏襲）。
- 反転には NoteArbitrationRationale（駆動源 notes／theory、
  音符の説明率と差、挑戦者の集計マージン、理論補助時は
  その項別内訳）を加算的に残す。理論の内訳は v2 の契約に
  倣い、emission と H は合計にのみ含め項目には載せない。
- 接続: 両経路とも最終段（候補露出の直後）。オプション
  `noteArbitration` が ON でも noteEvidence が無ければ
  **完全に無動作**。v1/v2 と同時指定した場合は本オプションが
  優先される（同時指定は測定対象外）。

## 2. 較正の根拠（真値なしプローブ＋設計検証）

閾値は評価スイートの正解では決めていない。本作業で実施した
真値なしプローブ（実曲 1〜3 両経路の baseline 候補列と選択
済み証拠のみ、正解ラベルは不使用、2026-10-29）:

- 割れたセグメント（勝者 ≠ 集計 argmax）は 507 件で、
  EVIDENCE_SELECTION の診断母集団と一致した。そのうち
  音符証拠が null／フォールバックで棄権になるのは 15 件。
- 集計 argmax のマージン（割れた側）: 中央値 −0.101、
  p25 −0.231、p75 −0.045。割れていない側の2位マージン:
  中央値 0.058、p75 0.095。接戦帯 0.06 は v1/v2 の
  emission 接戦域（emissionClamp = 0.06）と同値であり、
  「実曲で集計が曖昧な範囲の上限側」という同根拠（STEP2.md
  §2 のマージン分布プローブ）を引き継ぐ。帯の内側は
  全セグメントのうち接戦として扱う範囲であり、帯の外側は
  集計が現ラベルを明確に支持する側として対象から外す。
- 説明率差 Δ（割れた・棄権でない 492 件）: |Δ| の中央値
  0.283、p25 0.129。Δ > 閾値で反転する件数は閾値 0.05 で
  223 件、0.10 で 202 件、0.20 で 156 件、0.30 で 102 件。
  noteFlipDelta = 0.10 は (i) 「音符の重みの 10 ポイント差」
  という解釈可能な丸い値であり、(ii) |Δ| の中央値（0.283）
  を大きく下回るため極端な窓だけに絞る値ではなく、
  (iii) 証拠の薄いセグメントで生じるシェアの粗い量子
  （数音で 0.1 未満が揺れる）より上に置いた値である。
  正解率の分布は見ていない（診断 B の 0.745 は閾値なし＝
  Δ ≠ 0 の全数での値であり、本閾値はそれを狭める方向に
  しか働かない）。
- Song D 混合音では割れたセグメントが 8 件あり、Δ は全て
  正（最小 0.095、中央値 0.213）だった（記述統計のみ。
  基準4の合否は §4 の測定で判定する）。
- フィクスチャ窓の構造確認（§1.4 の Q2 のほか）:
  - stems-05 の Q3-B7 窓（87.63–89.30 秒）: 勝者 A、
    挑戦者 B は2位でマージン −0.586（集計が強く支持）、
    音符説明率は B 0.929 vs A 0.071（Δ = +0.858）。本設計で
    反転が起こる形になっている。なお否定保護の帯は
    「勝者より下の距離」にかかるものであり、集計が挑戦者を
    強く支持する側（マージンが深く負）にはかからない —
    B7 型の回収はこの非対称の上に成り立つ。
  - stems-05 の Q3-Am 窓: 両セグメントとも音符が現ラベル
    Am を支持する（Δ = −0.25／−0.10）。mixture-05 でも
    Am 窓のセグメントは音符が Am を支持する（Δ = −0.13）。
    v1/v2 が壊した Q3-Am は、本設計では音符段が能動的に
    守る側に回る。

## 3. 事前登録基準（測定前に登録。この基準で判定する）

標本規約・Δ の定義は STEP2_RETRY.md §3 と同一（0.05 秒標本、
labeled 基準、baseline は現行 top-1＝candidateRecord のみ）。
発火条件と改善ラインは経路別に登録する（仲裁力の経路差:
混合音 0.803 vs ステム 0.695、EVIDENCE_SELECTION §4.2）。

1. **非劣性（合成）**: 合成 A〜I 混合音の集計で root・triad の
   Δ が各 −1.0pt 以内。Song D ステムも同じ bound（音符
   キャッシュが other 側に無いため、本スイートでは評価器は
   入力なし＝無動作になり、Δ = 0 の見込みであることを
   ここに明記する）。
2. **改善（実曲）**: 実曲 1〜3 の集計で経路別に判定する:
   - 混合音: triad Δ ≥ +1.0pt、かつ root Δ ≥ −0.5pt、
     core Δ ≥ −0.5pt。
   - ステム: triad Δ ≥ 0.0pt、かつ root Δ ≥ −0.5pt、
     core Δ ≥ −0.5pt、かつ反転内訳の修正秒 ≥ 破壊秒。
     （ステムのラインが混合音より低いのは、診断でステムの
     仲裁力が勝者ベースライン比 +0.7pt と薄かったことに
     対応する。ステムで問うのは「害がなく、B7 型の回収が
     実際に起きるか」である。）
3. **フィクスチャ関門（ハード）**: Suno 05 両経路＋宵アーム B で:
   - **3a. Q3-Am 保全（独立項目）**: Q3-Am 窓（91–93 秒）で
     Am のラベル時間割合が全経路で baseline を下回らない
   - 3b. Q3-B7 窓（87–89 秒）: B major の割合が全経路で
     baseline を下回らず、かつ stems-05 では 34.0% 以上
     （v1 が回復した 68.3% の半分以上を維持する）
   - 3c. Q2 窓（153–168 秒）: Cm の割合が全経路で baseline を
     上回らない（棄却の維持）
   - 3d. Q1a（51–56 秒）・Q1b（93–98 秒）: C major の割合が
     全経路で baseline を下回らず、bassPc 一致率が baseline と
     同一。Q4 窓（62–65 秒）: C major の割合が全経路で
     baseline を下回らない
   - 3e. Q3-C（85–87 秒）・Q3-E7（89–91 秒）: 決着した読みの
     割合が全経路で baseline を下回らない
   - 宵アーム B には音符キャッシュが無いため、評価器は
     無動作になり全窓で baseline と一致する見込みである
     （基準5の「音符入力なしでは完全無動作」の実地確認を
     兼ねる）。
4. **Song D 混合音**: triad Δ ≥ +10.0pt。
5. **不変性と回帰**:
   - (a) noteArbitration OFF（明示 false）の全スイート署名が
     baseline と一致すること
   - (b) noteArbitration ON でも noteEvidence を渡さなければ
     全スイート署名が baseline と一致すること（完全無動作）
   - (c) N.C. 時間が全スイートで baseline と完全一致
     （変動 0 を bound とする）
   - (d) baseline と v1（初回主構成）の集計被覆が初回測定の
     保存値（theory-step2-results.json）と一致すること
     （theoryReevaluation.ts への export 追加が v1/v2 の
     挙動を変えていないことの確認を含む）
   - (e) 全テスト合格

報告には必ず以下を併記する: 反転の内訳（変更セグメント数、
標本ベースの修正秒／破壊秒／両誤り変更秒、経路別）、反転の
駆動源の内訳（notes／theory の件数と秒数）、理論補助 OFF の
ablation（実曲の集計被覆と Q3-B7／Q3-Am／Q2 のフィクスチャ
挙動。合否には使わない）。

**結論の置き方（事前に宣言する）**: 判定は経路別に行い、
経路で結論が分かれるのは構わない。ある経路で基準2を
満たさなければ、その経路での本消費形式は不採用とする。
基準 3a または 3c を満たさなければ、集計の合否によらず
全体を不採用とする。両経路とも基準2を満たさなければ、
「セグメント単位の音符仲裁」という本消費形式も閉じる
（第三の証拠そのものの成立は EVIDENCE_SELECTION で確定
済みであり、閉じるのはこの消費形式である）。合格した
経路については、オーナーの採用判断に委ねる材料として
提示するに留め、本作業では製品既定を変えない。

## 4. 結果

**総括: 主構成は事前登録基準を全て満たした（基準 1〜5 の
全項目が合格、経路別の基準2も両経路とも合格）。**
Theory Engine の再評価路線としては初めて、実曲の改善
ラインとフィクスチャ関門（Q3-Am 保全・Q2 の Cm 非復活・
Q3-B7 回復）を同時に満たした構成である。v1（実曲 triad
混合音 −4.8pt／ステム −7.6pt）・v2（同 −2.1pt／−1.5pt）が
いずれも実曲で差し引きマイナスだったのに対し、本構成は
混合音 +4.1pt／ステム +0.9pt と両経路でプラスに転じた。
改善の駆動源は音符段であり、理論補助の実曲への純寄与は
集計上ゼロだった（§4.3）。製品既定は変えていない
（noteArbitration は明示オプトインのまま）。

### 4.2 反転の内訳

標本ベース（triad レベル、秒）。修正＝誤り→正解、破壊＝
正解→誤り、両誤り変更＝誤り→別の誤り。

| 対象 | 反転セグメント | 修正 | 破壊 | 両誤り変更 |
|---|---:|---:|---:|---:|
| 合成 A〜I 混合音 | 14 | 8.2 | 0.0 | 1.4 |
| 実曲 混合音 | 78 | 41.3 | 10.5 | 120.7 |
| 実曲 ステム | 71 | 28.5 | 22.0 | 52.9 |

読み: 実曲の修正：破壊は混合音で約 4：1、ステムで約
1.3：1 であり、v2 の約 1：3 から比率が反転した。駆動源は
実曲ではほぼ全て音符段（混合音 77／78 件・174.3 秒、
ステム 70／71 件・103.1 秒。理論段は各経路 1 件のみ）。
両誤り変更は依然大きく、とりわけ実曲2（Everything）の
混合音で 86.3 秒ある — 語彙外コード・転調の多い曲では
三和音レベルの仲裁が誤り同士を入れ替える量が多い
（EVIDENCE_SELECTION §5 で指摘した物差しの限界）。
ただし同曲でも修正 17.9 秒 vs 破壊 1.2 秒で差し引きは
大きくプラスである。実曲3（A Hard Day's Night）の混合音
だけが曲単位で後退した（Δ −3.3pt、修正 0.4 vs 破壊
5.2 秒、反転 5 件）: 集計基準は満たすが、曲別の
ばらつきとして記録する。

### 4.3 理論補助の寄与（ablation。合否には使わない）

| 対象 | 主構成 triad Δ | 理論補助 OFF triad Δ | 理論補助の純寄与 |
|---|---:|---:|---:|
| 合成 A〜I 混合音 | +4.6pt | +1.4pt | **+3.2pt** |
| 実曲 混合音 | +4.1pt | +4.1pt | 0.0pt |
| 実曲 ステム | +0.9pt | +0.9pt | 0.0pt |

フィクスチャでも ablation は主構成と同一だった（B7
68.3%、Am 不変、Cm 11.0%）。帰属は明確である:

- **実曲の改善は音符段の単独寄与**であり、理論補助は
  実曲では集計上ゼロ（発火自体が各経路 1 件のみ）。B7 の
  回復も、v1 では集計 emission の加点（+0.19）が本体
  だったのに対し、本構成では音符説明率の差（Δ = +0.858）
  が本体であり、理論補助を切っても回復する。「集計が
  構造的に正しい場面」を、集計自身ではなく独立した証拠で
  回収できたことが、v1/v2 との決定的な違いである。
- 合成では理論補助が +3.2pt 寄与した。クリーンな合成音符
  では説明率が共有音に集中して同点（棄権）になりやすく、
  凍結した v2 構成がタイブレーカーとして健全に働いた
  （合成の破壊は 0.0 秒）。設計時の役割分担（主軸 =
  音符、理論 = 棄権時の補助）が、実測でもそのとおりの
  大きさに収まった。

### 4.4 Song D が v1/v2 の +19.0pt に届かなかった内訳

割れた 8 件のうち、Δ = 0.095 の 1 件が登録した閾値
（0.10）の僅差で不発に終わり、両誤り変更も 1.4 秒あった。
閾値は §2 の較正で事前に固定したものであり、結果を見て
動かすことはしない。登録した bound（+10pt）は満たして
いる。なお Song D の反転 3 件は全て音符段の駆動であり、
v1/v2 が集計追従で得た利得の大半を、独立した証拠でも
回収できることがここでも確認できた。

## 5. 結論

- **主構成は採用判断に進める状態になった。** §3 の事前
  宣言に従い、判定は経路別に行った: 混合音・ステムの
  両経路とも基準2を満たし、ハードゲート（基準 3a・3c）
  を含む全基準が合格したため、本消費形式（セグメント
  単位の音符仲裁＋理論補助）は閉じない。Theory Engine の
  再評価路線として初めて、実曲の改善とフィクスチャの
  保全・回復を両立した構成であり、STEP2_RETRY §5 の
  再開条件 (a) は「条件を満たす入力が揃った」だけでなく
  「その消費者も基準を満たした」まで進んだ。
- **ただし既定化は本作業の結論に含めない。** 製品既定は
  変えておらず、noteArbitration は明示オプトインのまま
  残す。製品で実際に使うには、ブラウザ Basic Pitch 推論
  （実測で関門通過済み）を製品に載せて音符証拠を実入力
  として供給する作業が前提になる（EVIDENCE_SELECTION
  §5 の指摘どおり）。採用と既定化は、その供給が揃った
  時点でオーナーが判断する。
- **理論項の位置づけは補助のまま確定する。** 実曲での
  純寄与はゼロであり、理論を主軸に戻す根拠は引き続き
  無い。一方で合成での寄与（+3.2pt、破壊ゼロ）と棄権時の
  受け皿としての健全性は実測されたため、凍結した v2
  構成の補助としての組み込みは維持する。
- **残る留保**（いずれも本構成の不成立ではなく適用範囲
  の限定として記録する）:
  1. 曲別のばらつき: 実曲3の混合音は後退した（−3.3pt）。
     集計は合格でも、全ての曲で改善するわけではない。
  2. 語彙外・転調の多い曲（Everything 型）では両誤り
     変更が大きい。三和音レベルの物差しの限界であり、
     拡張段の候補露出（第1段の引き継ぎ事項）が次の
     受け口になる。
  3. 境界汚染は未対処のまま（混合音-05 の B7 窓は
     不変）。noteBoundaries（既定 OFF）との併用効果は
     未測定であり、併用する場合は分離して数えること。
  4. ステムの改善幅は薄い（+0.9pt）。診断の予測どおり
     であり、ステム側の価値は集計の移動よりも
     フィクスチャ級の回収（B7・Q1b）に寄っている。
  5. 宵アーム B（Demucs 経路）は音符キャッシュが無く、
     本測定では無動作の確認のみ。Demucs の other から
     音符証拠を供給する場合の効果は未測定である。
