## 1. 目的と範囲

- 目的: ChordMini の出力（フレーム単位ラベル）を、既存の候補仲裁
  （noteArbitration と同じ狭い形）への**追加の証拠入力**として統合し、
  実曲・フィクスチャ・held-out での効果を、事前登録基準で測る。
- 統合は新しい明示オプション（既定 OFF、§12／未決点 D1）として実装
  する。製品既定は変えない。測定はローカルのみ（ブラウザ実装はしない）。
- 範囲外: モデル単独出力の採用、候補列そのものの変更、拡張段
  （第2段）へのモデルの直接接続（§10 基準2は「悪化させない」ための
  ガード測定としてのみ扱う）、Stage 2 の一切。

## 2. 結果の読み方についての留意点（結果文書への反映が必須）

Stage 1b の結果文書（CHORDMINI_STAGE1B_RESULTS.md を予定）は、
以下の3点を冒頭に明記し、結論の置き方に反映しなければならない。

1. **学習データ混入の可能性**: 学習コーパス（ラベル付きデータセットの
   正体）は公開情報で未確認であり、測定曲が学習に含まれている可能性を
   排除できない。実曲3曲はいずれも市販録音で、特に曲3
   （A Hard Day's Night、ビートルズ）は公開されている正解データが広く
   使われている曲である。Stage 1 で曲3のルートが 28.1% → 68.6% に
   跳ねた点も、混入の影響を受けているかもしれない。このため集計は
   「曲3を含む」と「曲3を除く」の両方を常に出し（§10）、混入の可能性が
   実質的に無い held-out（宵のひかり、§9.3）のフィクスチャ退行を
   ハードゲートとして重く扱う。
2. **統計**: 同じ曲のセグメントは独立ではなく、実質のサンプルは
   3曲程度である。フレーム／セグメント単位の p 値（Stage 1 で報告した
   p ≈ 2e-29 を含む）は根拠にしない。評価は曲単位を主とし、必要なら
   曲単位のブロックブートストラップによる区間推定を参考として添える
   （§11）。
3. **CQT の環境差**: Stage 1 の数字は librosa 環境での上限である。
   本ステージの測定値も同じ環境（librosa CQT + onnxruntime）のもので
   あり、ブラウザ CQT へそのまま移らない。

## 3. 入力契約: モデルのタイムラインをどう渡すか

noteEvidence（音符キャッシュ）がハーネスから解析オプション経由で
渡るのと同型に、ChordMini の出力を「モデルタイムライン」として
新しい入力フィールドで渡す。

- 形式: `ModelTimelineInput { frameDuration: number; labels:
  (string | null)[] }`。labels はフレームごとの語彙文字列
  （config.json の表記そのまま。例 "C:maj7"、"N"、"X"）。
  null はカバーなし（窓のパディング切り戻し部分など）。
- フレームの意味: Stage 1 のホスト契約どおり、**logits への一様
  移動平均（カーネル9フレーム）の後に argmax したラベル**。
  frameDuration は 2048/22050 秒（≈ 0.0929 秒）。
- Stage 1 の単独出力にあった「2フレーム未満の断片を長い方の隣接
  セグメントへ吸収する」セグメント化は**適用しない**。あれは単独
  出力の体裁を整える処理であり、票の集約（§4）はパイプライン側
  セグメントとの時間重なりで重みを付けるため、断片吸収はシェアを
  歪めるだけである。平滑化（カーネル9）までがモデルの契約であり、
  そこから先は消費者側の集約である、という線引きをここに明記する。
- 経路との対応（Stage 1 §7 仲裁診断の対応を踏襲する）:
  混合音経路 ← 混合音のラン、ステム経路 ← other ステムのラン。
  音符仲裁の和声プール（混合音経路 = 混合音の音符列、ステム経路 =
  other の音符列）と出所の対応を揃える。
- 生成と出自: タイムラインは Stage 1 の推論経路
  （scripts/chordmini/run_chordmini.py、librosa 0.11.0 +
  onnxruntime）で生成し、音符キャッシュと同じ置き場・同じ流儀で
  JSON キャッシュとして保存する。各キャッシュにはモデル revision と
  chordnet.onnx の blob ハッシュ（Stage 1 §0 の取得記録）を併記し、
  どの重みで作った票かを後から追えるようにする。音声・ステム WAV は
  従来どおりリポジトリに入れない。
- 製品接続はしない（Stage 2 の判断事項）。ハーネスが渡す場合にだけ
  存在する入力であり、未指定なら統合モジュールは音符仲裁単独の
  挙動に帰着する（§10 基準5b）。

## 4. 票の形式化: フレームラベル → セグメントの票

発火セグメント [start, end) ごとに、モデルフレームとの時間重なりで
票を集約する。

- フレームの重み = セグメントとの重なり秒数。
- 各フレームラベルは Stage 1 のマッピング表（CHORDMINI_STAGE1.md
  「ラベルマッピング」）で (root, コア major/minor/不定, 拡張クラス)
  に写す。写像は Stage 1 のものをそのまま再利用し、本ステージで
  変更しない。
- セグメントについて次を数える:
  - `coveredSec`: null でないフレームの重なり合計。
  - `coverage = coveredSec / (end - start)`。
  - `ncShare`: ラベルが N または X のフレームの重なり / coveredSec
    （モデルが「コードでない／同定不能」と言っている割合）。
  - `share(triad)`: root とコアがその三和音に一致するフレームの
    重なり / coveredSec。sus2／sus4 はコア不定のため**どちらの
    三和音にも数えない**（root のみの証拠であり、二択の票としては
    中立に置く。出自として rationale に sus のシェアを残す）。
  - 勝者（候補1位）と挑戦者（候補2位）について
    `modelDelta = share（挑戦者） − share（勝者）`。
- 棄権条件（モデルが発言しない）: coverage が §8 の T_cov 未満、
  ncShare が T_nc 超、modelDelta = 0（同点）、モデルの最有力三和音が
  勝者でも挑戦者でもない場合も票としては modelDelta の符号で扱うが
  （勝者・挑戦者への配分はそのまま数える）、最有力三和音が第3の
  三和音であることは rationale に記録する（格上げ先は常に挑戦者のみ
  であり、第3の三和音は §7 の否定保護により昇格できない）。
- モデルの票は三和音レベルである。拡張クラス（maj7／dom7 等）は
  本ステージの反転判定には使わない（候補列が三和音のみのため。
  拡張の証人としての利用は Stage 1 提言の別項であり、本ステージの
  範囲外。§10 基準2はガードとしてのみ測る）。

## 5. 発火条件: noteArbitration と同一の母集団

- 対象は noteArbitration と完全に同じ条件を満たすセグメントだけ:
  ラベルあり・装飾なし（extension／upperChord／addTones／ncFill は
  反転保護）・N.C. でない・候補が2つ以上あり1位が確定ラベルと一致し、
  **挑戦者 = 候補列の2位（candidates[1]）のマージンが接戦帯
  0.06 以内**にあるもの。接戦帯・保護規則は bd867ff の登録値を凍結
  してそのまま使う。
- 同一母集団にする根拠: (i) Stage 1 §7 の仲裁診断（正解率 82.4%）と
  EVIDENCE_SELECTION の仲裁診断（音符証拠 74.5%）はどちらも
  「勝者と集計 argmax が割れたセグメント」を母集団としており、
  noteArbitration の母集団はその登録済みの一般化（マージン < 0 の
  割れた側＋接戦帯の正側）である。モデルの仲裁適性が測られた土俵と
  統合先の土俵を揃えることで、診断値が消費者の期待値として意味を
  持つ。(ii) 作用範囲を構造で bound する本プロジェクトの採用
  パターン（noteBass・noteArbitration とも「狭く、証拠がある所
  だけ」）を維持する。
- **広げないもの（明示的に却下する代替案）**: モデルの最有力三和音が
  候補列の3位以下にある場合の昇格、接戦帯の外での発火、N.C.
  セグメントへのラベル付与。Stage 1 でモデルは Q2 窓に C:min を
  0.74〜1.67 秒出した — 単独モデルには本パイプラインの「証拠不足
  なら棄却する」規律が無く、母集団を広げるとその弱さがそのまま
  持ち込まれる。モデルの票は候補列の内側でのみ効かせる。

## 6. 組み合わせ規則: 音符とモデルの2証人チャンネル

noteArbitration の構造（主軸の証人＋棄権時の理論補助）を、証人を
2チャンネルに拡張する形で一般化する。各証人は独立に勝者と挑戦者を
評価し、自分の閾値で状態を返す:

| 状態 | 音符チャンネル | モデルチャンネル |
|---|---|---|
| 支持 SUPPORT | noteDelta > 0.10（凍結） | modelDelta > T_flip（§8） |
| 反対 OPPOSE | noteDelta < −0.10 | modelDelta < −T_flip |
| 弱い発言 WEAK | 0 < \|noteDelta\| ≤ 0.10 | 0 < \|modelDelta\| ≤ T_flip |
| 棄権 ABSTAIN | 証拠なし／フォールバック／同点 | §4 の棄権条件／同点 |

決定規則（発火セグメントごと）:

1. **反転**: 支持が1つ以上あり、反対が無い場合に反転する。
   駆動源は rationale に記録する（notes／model／notes+model）。
2. **拒否権（veto）**: どちらか一方でも反対があれば、もう一方が
   支持でも反転しない（証人の食い違いは現ラベルの維持で処理する。
   「強い証人が2人いて割れた」状況で片方に賭けないための規則）。
3. **弱い発言がある場合**: 支持も反対も無いが弱い発言が1つでも
   ある場合は現ラベルを維持し、理論補助も重ねない
   （noteArbitration の「主軸の閾値を補助で迂回しない」を
   2証人に拡張したもの）。
4. **全員棄権の場合のみ**: 理論補助（凍結した v2 構成の pairwise
   適用、noteArbitration §1.3 と同一・数値変更なし）が
   タイブレーカーとして働く。
5. モデル入力が無い場合は規則 1〜4 が現行 noteArbitration の
   決定表と一致する（音符チャンネルのみの表に帰着）。一致は
   §10 基準5b で全スイートのラベル同一性として検証する。

根拠内訳: 反転したセグメントには rationale を加算的に残す。
既存の NoteArbitrationRationale を拡張し、駆動源に "model" と
"notes+model" を加え、モデルの勝者／挑戦者シェア・modelDelta・
coverage・ncShare・sus シェアを項目として載せる（理論補助の
内訳の扱いは v2 の契約を踏襲する）。

代替案（主構成にはしない。ablation として報告のみ）:

- **優先順位型**: 音符を主軸とし、モデルは音符が棄権した接戦でのみ
  呼ぶ（noteArbitration の理論補助の席にモデルを座らせる形）。
  帰属は最も綺麗だが、モデルの仲裁適性（82.4%）が音符（74.5%）
  より高いという測定と、ステム経路で音符が弱い（0.695）場面こそ
  モデルが強い（81.1%）という測定を活かしきれない。
- **一致型（concordance）**: 両証人の支持が揃った場合だけ反転。
  精度は最も高い見込みだが、ステム経路では音符が棄権・弱発言に
  なることが多く、回収量が細る。
- **スコア融合型**: 両 delta を正規化して合算し単一閾値で判定。
  混合比という新しい調整パラメータが増え、寄与の帰属も濁るため
  本ステージでは採らない。

ablation として、音符のみ（= bd867ff 構成の再現）、モデルのみ、
優先順位型、一致型を同じハーネスで併記し、主構成の合否には
使わない（各証人の限界寄与を見えるようにするための報告である）。

## 7. 否定保護の適用

- 格上げできるのは candidates[1] だけであり、3位以下の候補は
  モデルの票がどれだけ強く支持しても復活させない。2位でも
  マージンが接戦帯を超える候補は対象外（§5 と一体）。
- N.C. セグメントには触らない（モデルの票でラベルを発明しない）。
  N.C. 時間は全構成で不変であることを §10 基準5d で確認する。
- Q2 の Cm についての構造的な説明: stems-05 の Q2 窓で現ラベルが
  Am のセグメントでは Cm は候補列の4位であり、モデルの票が Cm を
  向いていても挑戦者の席に着けないため格上げは起こらない
  （noteArbitration §1.4 の検証と同じ構造）。Stage 1 でモデル単独が
  窓内に出した C:min（0.74〜1.67 秒）は、仲裁の入力としては
  「勝者／挑戦者へのシェア配分」にしか変換されず、単独出力の
  ような形では現れない。ただし現ラベルが Cm 自身のセグメントや、
  Cm が2位にいるセグメントではモデルの票が Cm 側に効きうるため、
  フィクスチャ関門（§10 基準4）で実地に確認する。

## 8. 閾値の決定方針: 合成のみで調整し、実曲は検証専用

凍結するもの（bd867ff の登録値をそのまま使う。本ステージで動かさない）:
接戦帯 nearTieMargin = 0.06、音符の反転閾値 noteFlipDelta = 0.10、
理論補助 THEORY_WEIGHTS_V2 の全数値、候補列の定義（k = 5）。

新しく決めるもの（モデルの票に関する3つだけ）:

- **T_flip**: モデルチャンネルの支持／反対の閾値（シェア差）。
- **T_cov**: モデルが発言するための最小 coverage。
- **T_nc**: モデルが発言できる ncShare の上限。

決定手順（測定実施時にこの順序を守る）:

1. T_cov と T_nc は原則値で固定する: T_cov = 0.5（セグメントの
   半分以上をモデルフレームが覆っていること）、T_nc = 0.5
   （覆われた時間の半分超が N／X なら、そのセグメントでは
   モデルは実質「コードでない」と言っているため票にしない）。
   どちらも「半分」を基準にした解釈可能な値であり、微調整の
   対象にしない。
2. T_flip は**合成音源のみ**で決める。素材は合成 Songs A〜I の
   混合音（正解は完全）で、ChordMini のタイムラインを新規に
   生成する。各曲の baseline 候補列に対して §5 の発火母集団を
   作り、発火セグメントごとに modelDelta と「挑戦者が正解か
   勝者が正解か」を集める。候補グリッド {0.05, 0.10, 0.15, …,
   0.50}（0.05 刻み）の中で、**モデル駆動の反転の精度
   （修正秒 /（修正秒 + 破壊秒））が 0.90 以上になる最小の値**
   を T_flip とする。該当が無ければグリッド内で精度が最大の
   値（同点なら大きい方＝保守側）を採り、その事実を結果文書に
   明記する。
3. **十分性チェック（フォールバックの事前登録）**: 合成 A〜I で
   モデルが発言できる発火セグメントが 30 件未満、またはその
   母集団でモデルの票の正解率が勝者ベースラインを下回る場合は、
   合成がモデルの分布と合わず較正素材として不適格とみなし、
   T_flip = 0.10（音符の noteFlipDelta と同じ「重みの10ポイント
   差」という解釈可能な値）にフォールバックする。フォールバック
   した場合はその旨と根拠数値を結果文書に明記する。
4. 値が決まったら結果文書の事前登録節に凍結値を転記し、**以後は
   実曲の結果を見て動かさない**。実曲については真値なしプローブ
   （発火母集団での modelDelta の分布など、正解ラベルを使わない
   統計）を sanity 確認として実行してよいが、閾値の値決めには
   一切使わない。
5. ステム経路にも同じ T_flip を使う（経路別に決め直さない）。
   経路差は §10 の経路別ゲートで判定する。

- アーム C（Suno ステム経路）: モデル入力 = other ラン。

評価は**窓単位**である。各窓について決着した読みのラベル時間
割合を、同じアームの現在の既定の読みと比べて退行しないことを
見る（§10 基準4）。限界も明記する: 窓は曲の一部であり全曲の
ラベル列の正解は無いため、宵については root／triad の全曲
正解率は計算できず、言えるのはフィクスチャ級の保全・回復に
限られる。それでも「混入で説明できない素材で壊れない」ことの
証拠としては、実曲3曲の集計改善より重い意味を持つ、という
位置づけを事前に宣言する。

### 9.4 追加音源（ユーザーが用意する場合の条件案）

宵のひかりで held-out は1つ確保できるため、追加は必須ではない。
用意できる場合は曲単位の標本数が増え、§11 の統計が強くなる。
条件の提案（測定開始前に揃い、登録されたものだけを評価対象
にする。測定後に追加された素材は post-hoc として分けて報告する）:

- 形式: WAV または MP3（元のサンプルレートは問わない。解析側で
  従来どおり処理し、モデル側は 22050Hz へ変換する）。ステレオ・
  モノは不問。
- 長さ: 1曲丸ごとが望ましい（最低でも 90 秒以上）。
- 正解の付け方: (a) 全曲のコードチャート（開始–終了–ラベルの
  並び。ハーネスの正解形式に変換できる形）、または (b) 時刻つきの
  フィクスチャ窓（決着した読みを窓ごとに明記）。どちらもユーザーの
  耳による確認済みのもの。
- 素材の素性: 未発表の自作曲など、コード注釈つきで公開された
  ことのないもの（混入の可能性を低く保つため）。
- ステム: 無くてよい（混合音経路のみで評価できる）。ある場合は
  ステム経路も評価対象に加える。

## 10. 事前登録基準（確定案。承認をもって測定前に確定する）

標本規約・Δ の定義は noteArbitration の結果文書 §3 と同一
（0.05 秒標本、labeled 基準）。比較アームは同じハーネスで
再測定する: (0) 現在の既定（candidateRecord のみ）、
(1) noteArbitration（bd867ff の主構成）、(2) 統合（本設計の
主構成）。ablation（モデルのみ／優先順位型／一致型／理論補助
OFF）は報告のみで合否に使わない。過去の記録値は参考として
併記し、主判定には使わない。

1. **実曲の非劣性と改善（経路別）**: 混合音・ステムの各経路で:
   - 曲ごと（1〜3 の各曲）に triad Δ（統合 − 既定）が
     **0.0pt を下回らない**;
   - 3曲プール（時間加重）の triad Δ が**正**であること
     （混合音・ステムとも）;
   - ガード: プールの root Δ ≥ −0.5pt、core Δ ≥ −0.5pt;
   - ステム経路では反転内訳の修正秒 ≥ 破壊秒であること。
   報告には反転内訳（変更セグメント数、修正秒／破壊秒／
   両誤り変更秒、駆動源の内訳）を経路別に必須とする。
   集計は「曲3を含む」と「曲3を除く」の両方を出す。プールの
   改善が曲3を含む場合にのみ成立する（除くと正でなくなる）
   ときは、結論を「混入の影響を排除できない」に格下げする
   ことをここに登録する（数値ゲートとは別の、結論の置き方の
   規則）。
   （注記: 曲ごとの非劣性は noteArbitration の登録 —
   プールのみで判定し、曲3混合音の −3.3pt を「曲別の
   ばらつき」として記録した — より厳しい。オーナー案に基づく
   意図的な引き締めである。）
2. **拡張の誤発火ガード**: 拡張段を ON にした別アームで測る:
   現行第2段のみ（extensions: true、仲裁なし）と、第2段＋統合
   仲裁を比べ、plain な正解の時間における拡張つき検出の秒数が、
   曲ごと・経路ごとに**統合 ≦ 第2段のみ**であること。参照値
   （Stage 1 §4 の実測）: 曲3では第2段のみで混合音 72.6 秒／
   ステム 63.4 秒。仲裁はコアしか反転せず拡張を直接付けない
   ため、この基準は「コア反転が間接的に第2段の誤発火を増やさ
   ない」ことの検証である（拡張 OFF の構成では誤発火は定義上
   0 秒になり基準が無意味になるため、ON のアームで操作化する。
   §13 の承認点 D3）。
3. **仲裁の改善**: 割れたセグメントの母集団（EVIDENCE_SELECTION
   §2.2 の定義: 勝者と集計 argmax が割れ、正解がちょうど一方と
   一致する仲裁可能な標本）について、統合後のラベル正解率
   （triad、時間加重）が noteArbitration のみの場合を下回らず、
   プールで上回ること。経路別プールで判定し、曲別にも報告
   する。**曲3を除いたプールでも同じ方向（統合 ≥ 音符のみ）**
   であることを必須とする。証人レベルの票の正解率（統合規則が
   発火したセグメントでの正解率）も併記するが、合否は
   ラベル結果で判定する。
4. **フィクスチャの非退行（ハード）**: Suno 05 の両経路と
   宵のひかりの全アームで、現在の既定（アーム (0)）と比べて:
   - Q3-Am 窓: Am の割合が baseline を下回らない;
   - Q2 窓: Cm の割合が baseline を上回らない;
   - Q3-B7 窓: B major の割合が baseline を下回らず、かつ
     05 ステムでは 34.0% 以上（noteArbitration の登録フロアを
     踏襲）;
   - Q1a／Q1b／Q4 窓: 決着した読み（C major 系）の割合が
     baseline を下回らず、bassPc 一致率が baseline と同一;
   - Q3-C／Q3-E7 窓: 決着した読みの割合が baseline を
     下回らない。
   **宵のひかりのいずれかの窓で退行した場合は、実曲の集計に
   関わらず全体を不合格とする**（混入で説明できない素材での
   退行は、設計の欠陥とみなすため）。
5. **不変性と回帰**:
   - (a) 新オプション OFF のとき、全スイートの結果が現在の
     既定とビット一致すること;
   - (b) 新オプション ON でもモデル入力が無い場合は、全
     スイートのラベル列が noteArbitration（bd867ff）の主構成と
     完全一致すること（モデルの不在が音符仲裁の実測挙動を
     変えていないことの証明）;
   - (c) モデル入力はあるが音符入力が無い場合は、モデル
     チャンネルのみで §6 の規則が働くこと（理論補助は両証人
     棄権時に従来どおり）。製品経路ではこの状態は生じない
     （ハーネス上の定義確認として測る）;
   - (d) N.C. 時間が全アーム・全スイートで baseline と完全
     一致すること（変動 0 を bound とする）;
   - (e) 全テスト合格。
6. **感度**: 正解境界を ±0.3 秒ずらした再測定で、3曲プールの
   システム順位（(root + triad + core)/3 の平均による
   既定 < 音符仲裁 < 統合）が変わらないこと。曲別の入れ替わり
   は記録し、基準1のゲートを跨ぐ入れ替わりがあれば報告に
   明記する（Stage 1 基準6の「概ね合格」の運用を踏襲する）。

**結論の置き方（事前に宣言する）**: 判定は経路別に行い、経路で
結論が分かれるのは構わない。基準4（フィクスチャ、特に宵）を
満たさなければ集計の合否によらず全体を不採用とする。ある経路で
基準1を満たさなければ、その経路での本統合形式は不採用とする。
両経路とも基準1を満たさなければ、「ChordMini の票を候補仲裁に
組み込む」という本統合形式は閉じる（Stage 1 で測ったモデルの
単独性能・仲裁適性そのものは事実として残る）。合格した経路に
ついては、既定 ON の検討材料としてオーナーに提示するに留め、
本ステージでは製品既定を変えない。

## 11. 統計の扱い

- 主な評価単位は**曲**である。曲ごとの数値を常に出し、プールは
  時間加重の記述的な集計として扱う。
- フレーム／セグメント単位の p 値は根拠にしない（Stage 1 の
  p ≈ 2e-29 は Stage 1 の報告値としてのみ存在し、本ステージの
  判定には引用しない）。
- 必要なら、プールの triad Δ について曲単位のブロック
  ブートストラップ（曲をリサンプル単位とする 10,000 回）の
  区間推定を参考として添える。ただし標本が3曲では区間は広く
  ならざるを得ず、説得力の中心は「曲ごとの符号の一貫性＋
  フィクスチャのハードゲート＋held-out の保全」に置くことを
  明記する。追加音源（§9.4）が入れば、その曲も単位に含める。
