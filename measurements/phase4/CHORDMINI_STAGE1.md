  扱い、X の割合は別掲する

  算術平均（短い方に切り揃え）→ 同じ平滑化・セグメント化

### 判定ルール（事前登録した合格基準の操作化）

1. **基準1（主判定）**: 実曲3曲 × 指標（root／triad／core）× 曲ごとに、
   chordmini-mixture は今回再測定する混合音の現行既定と、chordmini-other と
   chordmini-combined はステム s-conditional の現行形と比べて「下回らない」
   （≧、小数第4位まで）ことを合格とする。全比較は表に併記する
2. **基準2（Q3）**: 85–93 秒を 2 秒ずつの小窓に分け、各小窓の過半ラベルが
   C（85–87）／B7（87–89）／E7（89–91）／Am（91–93）と一致すること。
   B7・E7 の小窓では dom7 クオリティが過半であることも要件とする
   （root＋三和音コアの一致だけでは「7th を読めた」とは言わない）
3. **基準3（Q2）**: 153–168 秒の窓で、C ルートの minor コア系ラベル
   （min／min6／min7／minmaj7／dim／hdim7／dim7）が 0 秒であること。
   内訳は品質別に併記する
4. **基準4（N.C.）**: N.C. 割合（N と X の内訳つき）を入力・曲別に報告する。
   合否は付けない
5. **基準5（拡張の誤発火）**: 正解に拡張が無い時間における「拡張つき検出」の
   時間を、現行第2段（extensions: true、混合音・ステム両経路）とモデル
   （3入力）で並べる。あわせて拡張つき正解への的中時間も報告する。
   フィクスチャ Q1（Am7 文脈）・Q3-B7／E7・Q4（CM7 系）でのモデルの読みも報告
6. **基準6（感度）**: 正解境界を ±0.3 秒ずらした再測定で、システム間の順位
   （曲ごとの (root+triad+core)/3、および3曲平均）が変わらないこと
7. 仲裁診断（報告項目）: EVIDENCE_SELECTION.md の方法を流用し、第1段候補で
   勝者と集計 argmax が割れたセグメントについて、経路に対応する入力
   （混合音経路↔mixture、ステム経路↔other）の ChordMini の票と正解率を出す

#### マッピングで落ちる情報（先に列挙する）

- **ベース音・分数・反転形が語彙に存在しない**: モデル出力からは bassPc /
  upperChord を一切得られない。層表示（Phase 3.2）の入力にはならない
- **9th／13th／add 系が無い**: 拡張は 7th 系と 6th 系まで。オーナーの様式語彙
  （maj9／maj13 等）の命名層にはそのままでは使えない
- **異名同音**: config.json はシャープ綴りのみ（Db 等は無い）。ピッチクラスへの
  変換では綴り情報は落ちるが、測定上の損失はない。なおモデルカードによれば
  チェックポイント内部の対応表は 70/170 インデックスで綴りだけが異なり、
  config.json はランナー側の語彙である
- **sus の 3 度**: sus2／sus4 は三和音コアが定まらない。物差しの都合で major
  として渡すため、sus 検出時間だけ triad 指標に偏りがありうる（別掲で上限を示す）
- **X（unknown）**: 「何か鳴っているが同定不能」のクラスを N.C. に潰す。
  N（無音・無コード）との区別は割合の別掲でのみ残る
- **信頼度**: フレーム logits は保持するが、ChordSegment.confidence に相当する
  集約値は今回の測定では作らない（セグメント評価は既存物差しのラベルのみ）

## 5. 基準6: 感度（正解境界 ±0.3 秒）

曲ごとの (root+triad+core)/3 の順位は、曲1・曲2では ±0.3 秒とも完全に

## 6. 失敗分析

未達はいずれも「文脈でこそ解ける」タイプに集中している:

1. **相対長調への吸収（曲3 core の主因）**: AHDN の拡張正解は実質2箇所。
   イントロの Fadd9（0.9–3.2s）を D:min7 と読み（構成音 F-A-C に G と D の
   取り違え）、141–150s の Dm7–Dsus4 反復を一貫して F と読んだ
   （Dm7 の相対長調）。どちらもベース音と前後関係があれば解ける誤りで、
   ベース情報を語彙に持たない単独モデルの構造的弱点
2. **ドミナントのモード反転（基準2の E7）**: 05 の E7 を E:min7 と読んだ。
   B7 は正しく読めているため一貫した弱点ではないが、V の 3 度の判定は
   モデルでも割れることがある、という記録
3. **短い Cm の出現（基準3）**: Q2 窓に C:min が 0.74–1.67 秒。
   現行パイプラインが「証拠不足で棄却」した読みを、モデルは弱く出す。
   仲裁の票としては有用でも、単独出力では棄却の規律が無い
4. **other 入力の N の多さ（05 で 33%）**: Demucs の other はベース・
   ドラム・ボーカルを欠き、モデルの学習分布（楽器ステム／混合音）より
   薄い。Q3-C 窓が全て N になったのはこの影響が濃い

逆に、現行パイプラインの弱点だった箇所（曲2 のような歌唱主体の曲での
root 崩壊、maj7 誤発火、B7 の読み）はモデルが明確に上回った。

## 7. 仲裁診断（4人目の証人としての適性）

第1段候補で勝者と集計 argmax が割れたセグメント（実曲・両経路プール、
仲裁可能 312 秒）での時間加重正解率:

| 証拠源 | 混合音経路 | ステム経路 | プール |
| --- | ---: | ---: | ---: |
| 集計 argmax | 40.9% | 31.1% | 35.7% |
| 現行勝者（ベースライン） | 59.1% | 68.9% | 64.3% |
| 選択済み音符証拠（EVIDENCE_SELECTION） | — | — | 74.5% |
| **ChordMini** | **83.7%** | **81.1%** | **82.4%** |

二項検定（セグメント単位）でも 208/247、p ≈ 2×10⁻²⁹ と偶然水準から
大きく離れる。特にステム経路で音符証拠（other の音符、0.695）より
明確に強いのは、モデルが「other のクロマ集計」とは独立な特徴
（学習された音色・ボイシングの型）を見ているためと考えられる。
棄権は両経路とも 21 秒（支持が同点のセグメント）。

注意: この母集団は現行候補列の「割れたセグメント」に限られ、
ChordMini の票は三和音レベル（root＋コア）で数えている。拡張の
仲裁適性は今回の測定範囲外。

## 9. Stage 2（ブラウザ実装）の見通しとリスク

- **CQT の等価性が必須級**: モデルカードは「librosa 等価でない特徴量は
  無料ではない」と明記し、nnAudio 代替で約 1.2% のフレームが落ちた
  実測を示している。ブラウザ側は @musetric/cqt（cqt-plan 方式の GPU CQT）
  を使う前提で、独自 CQT への差し替えは Stage 1 の数字を無効化する
- **WebGPU の無言誤計算の前例**: Adreno 660／750 で ORT WebGPU が
  静かに間違った logits を返した欠陥が2件記録され、配布中のグラフは
  静的書き換えで対処済みの版であることを確認した（バッチ16固定は
  その名残）。ただし当方の Basic Pitch 実測（2026-10-29）では別モデルで
  WebGPU EP 自体が失敗しており、端末差のリスクは残る。WASM
  フォールバック時の本グラフの速度は未測定
- **サイズと速度の見通し**: モデル 17.0MB＋plan 24KB は Demucs（172MB）
  より大幅に軽い。配布側の実測では 26–60 窓（約4–10分相当の窓数では
  ない点に注意: 108 フレーム≒10.03 秒／窓なので 26 窓≒4.3 分）が
  スマホ WebGPU で 0.5–1.3 秒。CPU 推論でも本測定一式（実曲3曲＋05、
  8 推論＋全解析）が VM（2 vCPU）で約2分に収まっており、特徴量計算を
  含めても実時間より十分速い見込み
- **メモリ**: [16,108,144] float32 の入力と中間層は数十 MB 級で、
  Demucs 級の圧迫はない見込み（実測は Stage 2 の範囲）

## 10. 提言

**Stage 2（置き換えとしてのブラウザ実装）には進まない。**

理由: (1) 事前登録した関門のうち3つ（core 曲3、Q3-E7、Q2-Cm）が未達で、
未達の型はすべてベース・文脈情報の欠落に由来し、移植では解けない。
(2) モデルは bassPc／層表示を原理的に出せず、置き換えると Phase 3.2 の
資産（層表示）が失われる。(3) ラベル付き学習データの出所が未確認のまま
公開物に組み込むのは時期尚早。

代わりに、次の測定ステージとして **「仲裁への統合」** を提案する:
noteArbitration と同じ枠組み（新たな事前登録）で、ChordMini の票を
候補仲裁の証拠源として測る。仲裁適性は今回 82.4% と測れており、
noteBass のように「狭く、証拠がある所だけ」使う形が本プロジェクトの
採用パターンに合う。あわせて、モデルの dom7／maj7 の読みは第2段
（拡張検出）の独立証人としても有望で、誤発火の少なさ（§4）は
その方向の測定を正当化する。

なお本測定の数字は librosa 環境のものであり、ブラウザ CQT へ
そのまま移らない可能性がある（§9）。将来 Stage 2 を再検討する場合は、
特徴量のパリティ検証から始めること。
