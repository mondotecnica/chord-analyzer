## 設定ごとの「勝ち方・負け方」（3 曲版）

- **phase0**: 曲1・曲2 ではほぼ最下位だが、曲3 ではルート
  最良（31.8%）になった。「土台として不足」は変わらないが、
  素の全帯域が相対的に有利なテクスチャもある。
- **bass（ベース補正）**: 曲1・曲2 では phase0 から一貫して
  改善したが、曲3 ではルートが −3.7pt 悪化した（低域の
  C#/D# ブリードで補正入力が汚れた可能性）。「悪化させない
  部品」ではなくなったが、悪化幅は小さく、平均では最良級。
- **default / band220（上帯域一括）**: 曲1 ではモード反転を
  治しつつルートを落とし、曲2 では最良。ところが曲3 では
  **ルート・コアとも最下位**に沈んだ。属音成分が支配的な
  テクスチャでは、低域を切るとルートの手がかりまで痩せる。
  2 曲時点の「一度も最下位になっていない」という性質は
  曲3 で崩れた。
- **hybrid（分業）**: 曲1 で全指標最良、曲3 でも三和音・
  コア最良（タイ）で、3 曲平均では全指標が最良または同点
  最良、最悪値でも三和音・コアが最良。負けは曲2（unified 系
  に劣後）と合成 Song D（ルート崩壊を直せない）の 2 件で、
  実曲の分数コード曲（曲2）では default とほぼ互角だった
  （コア 13.9% vs 14.1%）。
- **conditional（条件分岐）**: 実曲 3 曲を通して利益ゼロ
  （曲1 発火 0 件、曲2 発火 4 件・正解 0 件・有害 1 件、
  曲3 発火 0 件）。合成での理想的な振る舞いは実曲に
  転移しなかった。「合成専用の正しさ」で確定とする。

3 曲で確定したのは「効く構成は曲のテクスチャで決まる」
こと: 曲1 の主病はモード反転、曲2 はドミナントへの
ルート崩れ＋テンションの厚み、曲3 はドミナントへの引力＋
低域ブリード。単一の固定構成で全てに勝てるものは無かった。
その中で hybrid は「大きく勝つ曲があり、外す曲でも
崩壊しない」という実曲での分布が最も良かった。

キー推定は、ダイアトニックな三和音曲（曲3）では全設定で
正解した。誤った 2 曲はいずれも A minor に倒れており、
テンションや転調を含む曲での全体クロマ一括推定

発生し、帯域戦略と独立した課題として残る。

## Phase 1 で確立できたこと

1. **ベース補正は実曲でも概ね効く**（曲1・曲2 で一貫改善）。
   ただし曲3 で小幅に悪化させたため「無条件に安全な部品」
   ではなく、低域の証拠品質に依存する部品と位置づける。
2. **上帯域クロマはモード反転の特効薬**であり、実曲の
   最大級の誤り（曲1 の A → Am 56 秒）をほぼ消せる。
   合成の分数コード崩壊にも効く。一方、属音支配の
   テクスチャ（曲3）ではルートの手がかりまで削って
   最下位に沈む。効き方はテクスチャ依存で確定した。
3. **分業（hybrid）は実曲 3 曲で最も安定した構成**:
   モードだけ上帯域・ルートは全帯域＋ベース補正という
   分離が、モード反転（曲1）と属音引力（曲3）の両方に
   一定の耐性を持った。条件が合えば両取りでき（曲1）、
   合わない曲でも崩壊しない（曲2・曲3）。
4. **条件分岐は実曲では不発**: 崩壊シグネチャの前提
   （上帯域が健全なこと）が実曲の崩れ方と噛み合わず、
   3 曲で利益ゼロ。合成専用の機構として凍結する。
5. 測定基盤そのもの: 実曲＋再構成正解＋同一性検証
   （別曲ファイルの棄却を含む）＋感度チェック
   （±0.3 秒で順位不変を 3 曲とも確認）の手順が回り、
   数値を「暫定」と明記して比較できる状態になった。

## Phase 1 で解けなかったこと（次フェーズへの申し送り）

1. **キー推定**: テンション・転調を含む曲で 2/3 誤判定
   （どちらも A minor）。局所キー化と「硬いフィルタに
   しない」事前分布の設計は Phase 3 の課題。転調
   （曲2 の D♭ → D）は全体一括推定では原理的に扱えない。
2. **テンポの比率取り違え**: 倍取り（曲2）と 3:2
   （曲3）。オクターブ／比率補正は帯域戦略と独立した
   小課題として残る。
3. **テンション語彙**: 語彙外が正解の大半を占める曲では
   コア正解率の天井が低い（曲2 で最良 14.1%）。
   三和音コア確定 → 7th/9th 検出の二段判定が Phase 3 の
   本丸で、本総括の数値がそのベースラインになる。
   曲3 の冒頭和音（Fadd9 を全設定 Dm と読んだ）も、
   sus／add9 テンプレート導入時の再評価対象。
4. **実曲の分数コード**: 曲2 の分数小節 33 区間で、分数
   として完全正解は 1 小節のみ。ベース音をルートと分けて
   保持する仕組みはあるが、実曲の崩れ方（上帯域側も一緒に
   崩れる、ペダル音の主音誤読）には届いていない。
   ベースステムが分離できる Phase 2 で再挑戦するのが筋。
5. **属音への引力と低域ブリード**: 曲3 で新たに見えた
   病気。12 弦＋ボーカルの属音成分がテンプレート照合を
   V に吸わせ、低域では FFT ビン幅由来の隣接音級漏れが
   ベース証拠を汚す。どちらも「混ざった入力」への対症で、
   ステム分離（Phase 2）で入力自体を分けてから再測する。
6. **モード反転の根本原因**: 全帯域クロマがなぜ minor 側へ
   系統的に倒れるか（低域倍音・ボーカル等の寄与）は
   未解明のまま緩和策で凌いでいる。ステム分離後に
   「どのステムが反転を持ち込むか」を切り分けたい。

## 既定構成の推奨（最終判断はユーザー）

**推奨を改める: 既定候補は hybrid（分業: ルート＝
全帯域＋ベース補正／モード＝上帯域 260Hz）とする。**
2 曲時点の「default（上帯域一括）据え置き」推奨は、
3曲目の証拠で根拠が崩れたため撤回する。アプリの既定
そのものは変更していない（最終判断はユーザー）。

理由:

- 3 曲平均で hybrid はルート（35.0%、bass と同点最良）・
  三和音（39.5%、最良）・コア（27.0%、最良）の全指標で
  最良級。最悪値でも三和音 22.6%／コア 13.9% は全設定中
  最良で、「外した曲でも崩壊しない」性質が 3 曲で
  確認できた。
- default は曲3 でルート・コアとも最下位になり、
  据え置きの最大の根拠だった「全素材で最下位に
  なっていない」が崩れた。属音支配のテクスチャで
  一括上帯域が構造的に弱いことも分かった。
- hybrid の既知の弱点は合成 Song D のルート崩壊
  （26.7%、unified 260 の 87.2% に対して）だが、
  実曲の分数コード曲（曲2）ではその弱さは表面化せず
  （default と互角）、むしろ default の弱さの方が
  実曲（曲3）で表面化した。合成の誇張された条件
  （強い構成音ベース）よりも実曲 3 曲の分布を優先する。
- conditional は実曲で利益が観測されず（発火 0 件／
  4 件中正解 0 件・有害 1 件／発火 0 件）、既定にする
  根拠が無い。実験構成として保持し、Phase 2 の
  ステム入力でシグネチャの前提が変わった時点で再評価。
- なお Phase 2（ステム分離）が入ると、ベース／
  コード楽器のクロマが最初から分離されるため、帯域
  戦略の前提自体が変わる。既定の確定はその再測定後に
  再度行うのが合理的で、本推奨は Phase 2 までの
  「暫定の既定候補」という位置づけ。

Phase 1 はここで一区切りとする: 「ベース補正・上帯域・
分業という部品の効き方と限界が、合成と実曲 3 曲の
両方で測れた」ことが成果であり、残課題は Phase 2
（ステム分離による入力の分離）と Phase 3（テンション
二段判定＋局所キー）へ申し送る。

## 既定変更の実施記録（2026-10-27）

本総括の推奨を受け、ユーザーが **hybrid（分業）をアプリの既定にする**
ことを決定し、同日実施した。

- `AnalyzeOptions.bandStrategy` 未指定時の既定を `"unified"` から
  `"split"` に変更（`src/analysis/analyze.ts`）。ベース補正の既定 ON は
  従来通り。`"unified"` と `"split-conditional"` は明示指定の
  オプションとして引き続き利用可能。
- 履歴の再現性: 実曲ハーネス（scripts/measureReal.ts）の REAL_CONFIGS を
  改めた。旧 "default"（暗黙の既定頼み）は、全オプション明示の
  **"unified260"**（旧既定）として残し、新しい "default" は
  「全オプション未指定＝現在のアプリ既定（分業）」を意味するようにした。
  分業の明示指定は "hybrid" として併記する（将来の既定変更で
  「分業そのもの」の測定が化けないようにするため）。他の履歴ハーネスも
  `bandStrategy: "unified"` の明示固定を追加し、従来の記録がそのまま
  再現できることを確認した。既存の measurements/real/*/ の
  results.json・report.md は履歴記録として書き換えていない。
- 検証（2026-10-27）: 新既定で合成を再測定し、記録済みの分業の数値を
  再現した（Songs A–C ルート 95.4%／三和音 89.2%、Song D ルート
  26.7%）。実曲 1 曲目（Put Your Records On）でも、新 "default" が
  分業の記録値（54.1%／64.2%／31.1%）、"unified260" が旧既定の記録値
  （43.6%／51.2%／23.1%）を再現した。
- **受け入れた既知の回帰**: 新既定（分業）では、合成 Song D
  （分数コード）のルート正解率は 26.7% に留まる（unified の 87.2%
  に対して）。これは総括で検討済みの代償であり、隠さずここに明記する。
  分数コードの崩壊が支配的な入力では、明示指定の unified（または
  実験構成の conditional）が引き続き候補になる。
