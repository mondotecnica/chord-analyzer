# 実曲測定ガイド — Phase 1 Step 3 の回し方

合成音源での数字（ルート 96.9% / 三和音 92.1%）は最易条件の上限にすぎない。
Phase 1 の完了判定は、実曲 3 曲の測定を経てから行う（PHASE1_PLAN.md ステップ 3）。
このガイドは、その測定を実曲ファイルが届いた瞬間に回せるようにするための手順書。
測定そのものは `scripts/measureReal.ts` が担う。

## 用意するもの（1曲分）

1. **音声ファイル**（MP3 / WAV / m4a / ogg / flac）
   - 丸ごとでも、サビ等の区間だけでも可。最初は短い曲か区間が手順確認に適する。
   - MP3 等はハーネス側で ffmpeg により 44100Hz モノラルにデコードする
     （ブラウザの decodeAudioData は使わない）。WAV はそのまま読む。
2. **正しいコード進行**（下記の正解 JSON にする）
   - 自分で進行が分かっている曲が理想。
   - 曲名が分かれば公開コード譜を下敷きに作成することもできるが、
     譜面の転記ミスはそのまま測定誤差になるので、進行に確信のある曲を優先する。

## 実行コマンド

```bash
npm run measure:real -- --audio <音声ファイル> --truth <正解JSON> [--out <出力先>]
```

- `--out` を省くと `measurements/real/<曲名>/` に `report.md` と `results.json` が出る。
- 同じ曲を 4 設定で自動的に A/B 測定する（設定は `scripts/measureReal.ts`
  の `REAL_CONFIGS` 配列が唯一の定義。バリアント追加はそこに 1 行足すだけ）:
  1. `phase0`: ベース補正なし・全帯域（Phase 0 そのまま）
  2. `bass`: ベース補正のみ・全帯域（Step 1 の状態）
  3. `default`: 現在の既定（ベース補正＋上帯域 260Hz ハードカット）
  4. `band220`: ベース補正＋上帯域 220Hz

## 正解 JSON の形式

### (a) groundtruth 形式（最小例）

`test-audio/*.groundtruth.json` と同じ形。`key` と `bpm` は任意
（あれば検出値と比較する）。分数コードは `chord` とは別に `bass` で書ける。

```json
{
  "title": "曲名",
  "key": "C major",
  "bpm": 120,
  "durationSec": 32.0,
  "segments": [
    { "startSec": 0.0, "endSec": 8.0, "chord": "C" },
    { "startSec": 8.0, "endSec": 16.0, "chord": "Am" },
    { "startSec": 16.0, "endSec": 24.0, "chord": "F" },
    { "startSec": 24.0, "endSec": 32.0, "chord": "G" }
  ]
}
```

- コード名は拡張表記でもよい（`Cmaj7`、`C7`、`Am7`、`Cadd9`、`Csus4`、
  `C/E` のような分数表記、"Bb" のようなフラット表記も受理する）。
  拡張コードは後述の「コア正解」で判定される。
- 時刻は曲の頭からの秒数。区間は隙間なく並べるのが望ましい。

### (b) アプリの書き出しを正解にする方法（修正ワークフロー）

ACCURACY_MEASUREMENT.md の手順そのもの:

1. アプリ（またはプレビュー）で曲を解析し、解析直後の JSON を保存する
   （これは検出結果であって正解ではない）。
2. 画面上で誤っている区間を手動修正する。
3. 修正後に再度 JSON を書き出す。**この修正済み書き出しが正解 JSON になる**
   （形式は (a) と違うが、ハーネス側のアダプタが自動で判別して読み替える）。
4. その JSON を `--truth` に渡す。音声ファイルは元のものを `--audio` に渡す。

## 指標の読み方

- **ルート正解率 / 三和音正解率**（時間加重）: N.C.（無判定）区間は分母から
  除外し、N.C. 割合は別掲する。
- **コア正解率**: 正解が Phase 0 の語彙外（`Cmaj7` や `Cadd9` 等）の時間だけを
  対象に、検出のルート＋三和音コアが一致した割合。テンション曲を完全一致だけで
  測って実力以上に悪く見せないための別枠（対象時間が無ければ「—」になる）。
- **取り違え一覧**: 設定ごとに「正解 → 検出」の秒数上位。誤りの型
  （相対調の取り違え、major→minor 化、分数コードの崩れ等）を読む材料。

## Phase 1 の成否の目安（実曲）

- `default` が `phase0` を明確に上回る → ベース補正＋上帯域が実曲でも
  効いている。3 曲で再現できれば Phase 1 完了の根拠になる。
- `default` が崩れて `bass`（全帯域）が良い → 上帯域カットが実曲の帯域事情
  （低音域で弾かれるコード楽器等）と合っていない。固定値の再調整か、
  曲に応じた適応化が次の課題になる。
- `band220` が `default` を上回る → 境界は 260Hz で固定せず、実曲側に
  最適値がある可能性を示す。
- どの設定でもルートが崩れる曲がある → その曲の特徴（転調・分数・代理）を
  DESIGN_NOTES.md に追記し、Phase 2（ステム分離）の優先材料にする。

まず 1 曲で手順が回ることを確認し、3 曲まで増やしてから完了判定する。
