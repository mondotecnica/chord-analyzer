# フレームゲートの再設計 — 機構・設計・事前登録基準・結果

N.C. ラウンド（NC_ANALYSIS.md）の診断は、stems 経路の N.C. の主因が
「判定経路（other ステム）自身の中央値比で測る相対無音ゲート」である
ことを確定させた。本ラウンドは後段の介入ではなく、**ゲートそのもの**
を再設計する。進め方は従来どおり: 機構の文書化 → フラグ付き実装 →
本書 §3 に事前登録した基準で採用判定。

## §1 現行ゲートの機構（実測の失敗と対応づけて）

ゲートは `src/analysis/chordEstimation.ts` の `estimateChordFrames`
の1箇所だけにあり、両経路（混合音／ステム）が共有する。フレームは
次の2段で落とされる:

1. **無音ゲート**: しきい値 `T = max(median(E) × 0.15, 1e-4)`。
   フレームエネルギー `E[i] < T` ならクロマを照合する前に N.C.
   （信頼度 0）として確定する。`E` は computeChromagram の
   フレーム RMS で、**判定経路のエネルギー列そのもの**から中央値を取る:
   - 混合音経路: 混合音のエネルギー列。
   - ステム経路: **other ステムのエネルギー列のみ**。
2. **信頼ゲート**: 無音ゲートを通過したフレームだけが matchChord で
   照合され、コサインスコア < 0.55 なら N.C.。

失敗の機構（NC_ANALYSIS.md §3 の実測と対応）:

- 中央値比の規則は「曲の中での音量の強弱（ダイナミクス）」と
  「無音」を混同する。Demucs の other ステムはダイナミックレンジが
  広く、サビ等の大きな区間が中央値を決める。静かな和声区間
  （バースのパッド等）は other の中では 0.15×中央値を下回り続け、
  区間ごとフレームが全滅する。
- Suno stems の low-energy クラス 35.6 秒では、混合音側のゲート率は
  ほぼ 0（曲は通常の音量で鳴っている）で、落ちたフレーム群の
  エネルギー加重集計はテンプレートに 0.61–0.82 で明瞭に一致する。
  つまり証拠はフレーム列の中に実在するが、ゲートが二値で先に
  落とすため、セグメント集計の出番が来ない（セグメントは N.C.
  として確定し、後段は既定では再判定しない）。
- 逆に、曲自体が静かな箇所（曲頭／曲尾のフェード、ブレイク、
  AHDN の曲尾、Suno のアウトロ）では混合音側もゲート率 1.0 に
  なる。ここでの N.C. は正しく、ゲートの本来の仕事である。

NC ラウンドが全体引き下げ（0.15 の係数変更）を採らなかった理由も
機構から言える: しきい値は曲全体・経路全体に効くため、正しい
N.C.（合成のフェード等）まで一様に書き換わり、かつ「参照が
ステム自身である」という概念的な誤りは残る。

## §2 再設計: 曲参照ゲート（song-referenced gate）

**原則**: 無音ゲートが答えるべき問いは「この瞬間、曲が鳴っているか」
であり、「このステムが自分の中中央値と比べて大きいか」ではない。
ステムが相対的に静かなことは無音ではなくダイナミクスである。
よって参照を判定経路から曲全体（混合音）へ移す。

**規則**（`frameGate: "song-referenced"`、フラグ付き）:

- フレームが無音ゲートで落ちるのは、**両方**を満たすときだけ:
  - 判定経路: `E_j[i] < T_j`（現行の相対規則、そのまま）
  - 参照経路（混合音）: `E_r[i] < T_r`（同じ 0.15×中央値の式を
    混合音エネルギーに適用）
- さらに救済には絶対フロアを課す: `E_j[i] >= F`、
  `F = max(median(E_j) × rescueFloorRatio, 1e-4)`。
  原則点は `rescueFloorRatio = 0`、すなわち `F = 1e-4`。これは
  現行式にもともと入っている絶対下限（デジタル無音の保護）であり、
  新しい調整パラメータではない。
- 信頼ゲート（0.55）、matchChord、セグメンテーション、下流の
  全段階は不変。救済されたフレームも1フレームずつ信頼ゲートを
  通り、メディアンフィルタ（5フレーム）と最小セグメント長に
  かかる。救済 ≠ 自動ラベル付け。

**混合音経路では現行と完全一致する**: 参照 ≡ 判定経路なので
AND 条件は現行規則そのものに帰着する。これは設計上の性質であり、
単体テストとハーネスの両方でビット一致を assert する。診断が
あるのはステム経路だけなので、影響範囲もステム経路だけになる。

**全体引き下げとの違い**: 曲自体が静かな箇所では参照側も落ちる
ため、フェード・ブレイク・曲尾は現行どおり落ちる。状態が変わる
のは「曲は鳴っているのにステムだけが相対的に静か」なフレーム
だけであり、これは診断が特定した失敗クラスそのものである。

**フロンティア**: `rescueFloorRatio ∈ {0, 0.03, 0.05, 0.10}` を
ステムスイートで測る（0.15 で現行に帰着）。比率 0 の原則点で
どこまで回復し、正の比率（ブリード対策の床）が何を代償に何を
守るかを、単一の調整点ではなく曲線として記録する。

**もう1つの候補（セグメント整合ゲート）の評価**: 落ちたフレームを
「区間集計と整合する場合に投票させる」方式は、本ラウンドでは
ゲート内蔵の形では実装しない。理由は測定前に明記する:
(a) その区間レベルの形は既に ncSegmentRematch として存在し、
単独では正誤比 1.14× と弱い弁別力であることが実測済み
（集計の一致だけでは不十分）。(b) フレームレベルの整合性は
既存の信頼ゲート＋メディアンフィルタが既に担っている。
(c) 診断が特定した機構は「参照の取り違え」であって「整合性
証拠の不足」ではない。代わりに、組み合わせアーム
（新ゲート＋rematch）で「新ゲートの残りに対して区間レベルの
整合が上乗せできるか」を測る。

## §3 事前登録: 採用基準（最終測定の実行前に本節を登録した）

アーム構成:

- ステムスイート（実曲 1–3、Song D、Suno）:
  legacy / song（比率 0） / r03 / r05 / r10 /
  song+rematch / song+rematch+gapfill
- 混合音スイート（合成 A–I、実曲 1–3、Suno）: legacy / song
  （帰着の検証専用）

各アームで記録する: N.C. 割合、精度（合成: root/triad＋AllTime、
実曲: root/triad/core）、legacy の N.C. 時間に対する変換会計
（正解／誤り／据え置き／未検証、0.05 秒サンプリング、NC_ANALYSIS
§5 と同義）、legacy の判定済み時間に対する churn 会計
（正→誤、正→N.C.、誤→正、誤→別誤り）。

- **P1 主要基準**: Suno stems の N.C. 割合が `song`（比率 0）で
  **16.0% 以下**（NC ラウンドの目標をそのまま引き継ぐ。根拠:
  Suno stems の N.C. 46.7 秒中 35.6 秒 ≈ 全体の 17.4pt が
  low-energy クラスで、その大半は混合音ゲート率 ≈0 の区間。
  ただし最終値は信頼ゲートとセグメンテーション通過後の
  セグメント単位の N.C. で測るため、自動的には達成されない）。
- **P2 精度ガードレール（ステム）**: 実曲 stems 各曲の
  root / triad / core が legacy 比で各 **−1.0pt 以内**
  （NC_ANALYSIS §5-b と同幅）。Song D の root / triad も同幅。
- **P3 churn**: 実曲 stems＋Song D の各スイートで
  「正→誤」と「正→N.C.」の合計が曲長の **0.5% 以下**、かつ
  対象スイート合計で「誤→正」>=「正→誤」。
  「判定済み→N.C.」の churn は新ゲートが開く方向しかないため
  ≈0 のはずだが、セグメンテーション経由の境界移動は正直に数える。
- **P4 真の無音 = 違反 0**: Suno アウトロ（開始 201 秒以降）が
  両経路・`song` で全て N.C.。AHDN の [正解終了 150.1 秒, 曲尾]
  が両経路・`song` で全て N.C.。
- **P5 帰着**: 混合音スイート全てで `song` の出力（セグメントの
  境界・ラベル・信頼度、キー、BPM）が legacy とビット一致。
- **P6 フィクスチャ**: Suno Q1 pass / Q2 stage2Pass / Q3 pass /
  Q2 窓の Cm 秒数が legacy と `song` で一致（拡張 OFF/ON とも。
  NC ラウンドの照合方法を踏襲）。
- **P7 回復との関係**: NC ラウンドの legacy+all は Suno stems
  19.9% だった。`song` 単独がこれを下回らないなら、ゲート再設計は
  棄却済みスタックに対して何も加えていないことになるため、
  P1 の内訳として `song` 単独 < 19.9% を必須とする。併せて
  song+rematch の「新ゲート残余への変換」を NC_ANALYSIS §5 の
  主要基準（>= 2.0× かつ >= 5.0 秒）で判定し、rematch が
  新ゲート後も生きた候補か、ゲート起因分については superseded か
  を記録する。

**採用規則**: P1–P7 を全て満たせば `song`（比率 0）を既定化する
（旧ゲートは明示オプトアウトとして残す）。比率 0 で P1 に届かず
正の比率でのみ全基準を満たす場合は、自動的には採用しない:
フロンティアを報告し、比率の根拠が機構（ブリード床）から
言える場合に限って採用候補として文書化する。逆に比率 0 が
P1 を満たすのに、数字合わせのためだけに正の比率を採ることは
しない。どの点でも精度・churn の基準を満たさなければ不採用とし、
フロンティア（どの設定がどの交換をしたか）を §4 に残す。

## §4 結果

測定: scripts/measureGate.ts（`npm run measure:gate`、生成物:
frame-gate.json）。2回実行して数値の一致を確認した（本節は
2回目の生成物に基づく）。legacy アームは記録ベースライン
（nc-recovery.json）と一致することをアンカー assert で確認した
（Suno 混合音 5.2% / ステム 22.8%、曲1 stems 6.9%）。

### N.C. 割合（ステム経路）

| スイート | legacy | song（比率0） | r03 | r05 | r10 | song+rematch |
| --- | --- | --- | --- | --- | --- | --- |
| Suno ステム | 22.8% | **3.3%** | 10.5% | 15.2% | 18.9% | 3.3% |
| 曲1 ステム | 6.9% | **1.2%** | 3.6% | 4.7% | 6.4% | 1.2% |
| Everything ステム | 5.7% | **3.8%** | 5.5% | 5.5% | 5.6% | 2.5% |
| AHDN ステム | 4.4% | 4.4% | 4.4% | 4.4% | 4.4% | 4.4% |
| Song D ステム | 4.5% | 4.5% | 4.5% | 4.5% | 4.5% | 4.5% |

混合音経路は全スイート（合成9＋実曲3＋Suno）で song = legacy の
ビット一致（P5）。AHDN と Song D のステムで全アーム不変なのは、
この2曲の N.C. が「混合音側も落ちる真の低エネルギー／スコア
不足」主体で、救済の対象（混合音と other の不一致）が存在しない
ためであり、診断どおりの選択性である。Suno ステムでは混合音
経路の 5.2% をも下回った（3.3%）。

### 精度（ステム、legacy → song の差分 pt）

| スイート | root | triad | core |
| --- | --- | --- | --- |
| 曲1 | −0.36 | −0.83 | −0.21 |
| Everything | +0.19 | +1.07 | −0.27 |
| AHDN | 0.00 | 0.00 | 0.00 |
| Song D | 0.00 | 0.00 | — |

全て P2 の許容幅（−1.0pt 以内）の中。フロンティア点では曲1の
triad が r05 で +0.46 に転じる一方、Suno は 15.2% まで悪化する。
比率を上げるほど回復が減る単調な交換であり、比率 0 を支配する
点は無い。

### 変換会計と churn（song アーム）

- 変換（legacy の N.C. → 判定）: 実曲ステム合計で正解 9.40 秒 /
  誤り 11.30 秒（曲1: 6.75 / 5.80、Everything: 2.65 / 5.50）。
  **実曲の静かな区間で救済されたフレームの投票精度は約 45%** で、
  other の証拠自体が弱いこと（NC ラウンドの曲1監査）と整合する。
  Suno では 47.4 秒中 40.6 秒が変換された（正解なし。フィクスチャ
  不変、下記）。
- churn（legacy の判定済み時間）: 「判定済み → N.C.」は全スイート
  0 秒（ゲートは開く方向にしか働かず、判定済みフレームの投票は
  失われない）。「正 → 誤」は曲1 0.10 秒＋Everything 0.05 秒の
  合計 0.15 秒、「正 → N.C.」0 秒、「誤 → 正」0 秒、
  「誤 → 別の誤り」1.75 秒（セグメンテーションの境界再編）。
  スイート別の悪化 churn は曲長の 0.047% / 0.012% / 0% / 0% で、
  P3 の主条項（0.5% 以下）は予算の 1/10〜1/40 で合格。

### 基準ごとの判定

- **P1 主要基準: 合格**。Suno ステム 3.3%（目標 16.0% 以下、
  5倍の margin）。
- **P2 精度ガードレール: 合格**（上表、全項目 −1.0pt 以内）。
- **P3 churn: 主条項は合格、合計条項は字義どおり未達**。
  「誤 → 正（合計）>= 正 → 誤（合計）」に対し実測は 0 秒 vs
  0.15 秒。差分は会計のサンプリング量子（0.05 秒）3個分で、
  判定済み時間 約810 秒の 0.02% にあたる（§5 で扱う）。
- **P4 真の無音: 合格**。NC ラウンドの運用定義（ウィンドウ以降に
  始まるセグメントは全て N.C.）では全アーム・両ウィンドウとも
  違反 0。重なり秒数で見ると Suno ウィンドウには全アーム共通で
  0.13 秒の重なりがあるが、これは legacy 自身が持つ「境界を
  またぐ最後の実コード（201.13 秒まで）」の残響であり、どの
  アームも増やしていない。AHDN ウィンドウの重なりは全アーム 0。
- **P5 帰着: 合格**。混合音 13 スイート全てでセグメント列
  （境界・ラベル・信頼度・付帯情報）がビット一致（ハーネスと
  単体テストの両方で assert）。
- **P6 フィクスチャ: pass 判定は一致、Cm 秒数の厳密一致のみ未達**。
  Q1 pass（false）/ Q2 stage2Pass（false）/ Q3 pass（true）は
  legacy と song で一致。Q2 窓の Cm 秒数は 4.75 → 4.80 秒で
  +0.05 秒（境界 1 フレーム分）の差が出た。
- **P7 回復との関係: 合格**。song 単独（3.3%）が legacy+all
  （19.9%）を大きく下回る。新ゲートへの rematch の上乗せは、
  Suno では変換ゼロ（完全一致）、実曲ステムでは正解 +0 秒 /
  誤り +0.05 秒 / 未検証 +5.45 秒（Everything 冒頭の正解不在
  区間への充填。NC ラウンドで見たのと同じ病巣）で、残余に
  対する NC_ANALYSIS §5 の主要基準（>= 2.0× かつ >= 5.0 秒の
  正解変換）を満たさない。gap-fill の上乗せも変換ゼロ。
  **rematch はゲート起因の N.C. については superseded** であり、
  残余に対しても生きた候補ではないことが確定した。

## §5 採用判定

**採用する: `song-referenced`（救済フロア比率 0）を両経路の
既定とし、`legacy` は明示オプトアウトとして残す。**

実施内容: analyze.ts / analyzeStems.ts の `frameGate` 既定を
"song-referenced" に変更（アプリの高精度モード入口もこの既定を
受ける）。履歴再現ハーネス（measureNc / measurePhase3 /
measurePhase32 / measurePhaseGenre / measurePhaseMeter）は
記録ベースラインが legacy ゲート時代のものであるため、
`frameGate: "legacy"` を固定した（各ファイルに明記）。
measureStems は内部の測定呼び出しのみ固定し、再エクスポートは
アプリ既定のままにした（Phase 2 の生成物が再実行で書き換わら
ないことも確認）。アプリ経路テスト（analyze-stems-app-path）は
記録 JSON への一致でなく「共有コアの現行既定との一致」を検証
する形に更新した（記録 JSON の再現は measureStems 側が担う）。

判定の根拠と、未達点の開示:

- 主要基準 P1 は 5 倍の margin で合格し、P2・P4・P5・P7 は
  完全合格だった。機構の誤り（参照の取り違え）を機構で直す
  という本ラウンドの主張は、実測で裏付けられた。
- **2つの副条項は字義どおり未達であり、事後に基準を書き換えて
  「全て合格」とは言わない**: P3 合計条項（0.15 秒）と P6 の
  Cm 秒数の厳密一致（+0.05 秒）。どちらも量子 1〜3 個分の
  境界移動であり、P3 の主条項は 1/10〜1/40 の使用率で合格
  している。効果量の非対称性（ユーザーの自作曲で 19.5pt の
  N.C. 解消、実曲 stems でも 5.7pt / 1.9pt の解消 vs 合計
  0.2 秒の境界ノイズ）をもって、採用側に倒す判断をする。
- 代償の正直な記録: 実曲の静かな区間では、救済されたフレームの
  投票精度は約 45% にとどまる。「分からない（N.C.）」だった
  区間に当たり外れのあるラベルが付くようになるのがこの変更の
  本質であり、精度指標が悪化しないのは変換量が判定済み時間に
  比べて小さいためでもある。信頼ゲート（0.55）はこの代償を
  抑える要として現行のまま維持する。Suno 型の素材（集計
  スコア 0.61–0.82、混合音ゲート率 ≈0）では変換は健全に
  働いている。
- N.C. 回復 3 介入の位置づけ: NC_ANALYSIS §7 の「3介入とも
  不採用」は新ゲート後も維持される（rematch は superseded、
  fallback は有害のまま、gap-fill は上乗せ効果ゼロ）。各介入は
  引き続き既定 OFF のオプトインとして残る。
- 残る N.C.: Suno ステム 3.3%、実曲ステム 1.2〜4.4%。残余の
  主体は信頼ゲート側（スコア不足）と真の低エネルギーであり、
  フレームゲートの担当範囲外である。
