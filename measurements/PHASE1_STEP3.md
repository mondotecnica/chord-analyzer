## なぜ Step 3 が必要か

合成音源での上帯域 260Hz ハードカットは、Song D（分数コード）で
ルート 26.7% → 87.2%、Songs A–C で 95.4%/86.4% → 96.9%/92.1% と改善した
（measurements/PHASE1_UPPERBAND.md）。ただし合成音源はコード楽器の
基本波がすべて 261.6Hz 以上という一番易しい条件で、実曲では低音域で
コードを弾くギターやピアノ、ボーカル、ドラムのキックまで混ざる。
260Hz カットが実曲でも正解とは限らないため、設定を固定で信じずに
測るのが Step 3 の目的。

## 比較する 4 設定

| 設定 | ベース補正 | コード判定クロマ |
| --- | --- | --- |
| phase0 | なし | 全帯域（フェーズ0そのまま） |
| bass-only | あり | 全帯域 |
| current | あり | 上帯域 260Hz ハードカット（現在の既定） |
| cut220 | あり | 上帯域 220Hz ハードカット（境界の別バリアント） |

この比較で分かること: 合成で勝った設定が実曲でも勝つか、帯域の最適値が
実曲では違うか。実曲でも上帯域が効けばフェーズ1完了としてフェーズ2
（Demucs 準備）へ。実曲で崩れるようなら、帯域を固定値ではなく曲に応じて
適応させる方向がフェーズ1.5の課題になる。

## 進め方（1 曲だけから始める）

1. コード進行が分かっている曲の MP3 を 1 曲用意する（丸ごとでも、
   サビだけのような一部でも可）。
2. MP3 を WAV に変換する（ffmpeg は確認済み）:
   `ffmpeg -y -i song.mp3 -ac 1 -ar 44100 -sample_fmt s16 test-audio/step3-song.wav`
3. 正解進行 JSON をテンプレートの形で用意する
   （measurements/step3-truth-TEMPLATE.json を複製して書き換える）。
   コード名はシャープ表記（"C", "Am", "F#" など。フラットは "A#" のように
   読み替える）。分数コードは "C/E" の形で書けばルートとベースに分けて扱う。
   テンション・7th を含む曲は Phase 0 の語彙外のため、まず三和音中心の
   曲か、三和音コアで区切った区間から始める。
4. ハーネスで 4 設定を回し、このファイルに結果レポートを追記する。
   実曲ファイルと正解 JSON は、公開時に音源を保存しない方針と区別するため
   測定用の一時ファイルとして扱い、レポートには数値と曲名・区間のみ残す。

### TRUTH_NOTES — 正解の構築方法・前提・曖昧さ

小節グリッドの固定方法:

1. パイプライン（default 設定）を 1 回回し、検出 BPM = 96 を得た。
2. オンセット包絡へのコムフィルタ照合で周期 0.6250 秒（= BPM 96.00
   ちょうど）が最良（平均の 1.75 倍）と確認した。クリックなしの
   スタジオ録音でテンポドリフトは見られない前提で、拍周期は
   0.625 秒に固定した。
3. ダウンビート位相は、フレームクロマの新規性（変化量）が小節頭に
   集中する回転を選んだ（位相 0.216 秒、集中度比 1.29、他候補は
   1.09 以下）。小節長 2.5 秒 × 85 小節で 212.72 秒 ≈ 曲長 212.67 秒。
4. セクション境界は、検出セグメントのパターン、0.1 秒集計クロマの
   小節別テンプレート照合、低域（ベース）分布、エネルギー推移から決めた。
   ループ区間はベース音の循環（A → F# → E → A）が小節単位で追える。

仮定したセクション構成（計 85 小節）:

| セクション | 小節 | 小節数 |
| --- | --- | --- |
| イントロ | 1–3 | 3 |
| Aメロ 1 | 4–11 | 8（ループ×2） |
| プレコーラス 1 | 12–19 | 8 |
| サビ 1 | 20–29 | 10（ループ×2＋Dmaj7 — Dm(maj7) の尾） |
| ターンアラウンド | 30 | 1（A） |
| Aメロ 2 | 31–38 | 8（ループ×2） |
| プレコーラス 2 | 39–46 | 8 |
| サビ 2 | 47–56 | 10（ループ×2＋尾） |
| ブリッジ | 57–67 | 11 |
| サビ（最終） | 68–80 | 13（ループ×3＋最終 A） |
| アウトロ | 81–85 | 5 |

表記上の曖昧さ（2件、明示する）:

- **F#m6 vs D#m7♭5**: 同一音集合（F# A C# D#）。ユーザーの主表記
  F#m6 で符号化した（コアは F# minor）。イントロ 2 小節目は低域で
  D# が強く、D#m7♭5 読みも音響的には支持される。コア判定には影響しない。
- **Dmaj7/E vs E9/E13**: ループ 3 番目の小節は、譜面により E ルートの
  ドミナント（E9/E13）とも表記される。ここではユーザーの主表記に従い
  「コード = Dmaj7、ベース = E」（別フィールド）で符号化した。
  ただしこの判断は測定に効く: 該当は 11 小節・約 27.5 秒（曲の約 13%）
  で、もし実際は E ルートなら、その区間のルート正解率は別物になる。
  検出側はこの区間を A や Dm と読むことが多く（後述）、E と読む例は
  少ないため、E 符号化に変えてもルート正解率が大きく上がる見込みは
  薄いが、断定はしない。

信頼度の低い正解箇所（復元の限界）:

- ブリッジ（57–67 小節）: 低域が B に張り付く区間を Bm7 のペダルと
  読んだ（57, 58, 60, 61, 62 小節）。63 小節は前半 Dmaj7／後半 Bm7 の
  半小節分割、64 = Dm(maj7)、65 = A、66 = F#m、67 = Dmaj7/E
  （最終サビへのピックアップ）。ユーザーの言う「派生コード」の範囲で
  解釈したが、この 11 小節は全体で最も確信が低い。
- 最終サビ 71・75 小節: 他のループ 3 小節目と違い低域に E がなく
  B／F# が支配的なため、Dmaj7/E ではなく Bm と符号化した（変奏と判断）。
- アウトロ 82 小節: F のクロマ＋G の低域から G9 と符号化（確信低）。
  83–85 小節は A（最終和音）。
- プレコーラスの尾: Dmaj7 の次に Dm(maj7) が続く点はユーザー情報通り
  だが、その持続小節数（PC1 は 17–19a 小節、PC2 は 44–46 小節）は
  低域 D の持続からの推定。19 小節後半は A への移行が明瞭だったため
  半小節で分割した。

時刻の不確実性:

- グリッド自体の残差は ±0.15 秒程度と見積もる（位相推定の分解能と
  新規性集中度の合い方から）。セクション境界はブリッジ／アウトロで
  ±1 小節の余地がある。
- 感度チェック（後述）: 正解境界を一律 ±0.3 秒ずらしても default の
  ルートは −1.3〜−1.0pt、三和音は −0.7〜−1.6pt、コアは −2.1〜+0.6pt
  しか動かない。つまり以下の低調な数字は、グリッドのずれではなく
  検出そのものの性質とみてよい。

### 暫定所見（Phase 1 完了とは判定しない）

合意した判断枠組み「実曲でも上帯域が勝てば Phase 1 完了」に対して、
この曲では答えは単純ではない:

- 上帯域（default）は、合成音源では見えなかった実曲固有の最大の病気
  ―― 全帯域クロマの major → minor 系統的反転（A → Am 56 秒）―― を
  大幅に治した（三和音 1.3% → 51.2%、モード誤り 80.5 秒 → 18.3 秒）。
- しかしルート正解率は phase0 の 50.5% から 43.6% へ悪化した。
  上帯域はルートを決める低域の手がかりを捨てるため、検出が
  3 度・5 度関係のコード（Dmaj7 → A、A → C#m）へ流れる。
  ルートだけなら bass（全帯域＋ベース補正）が最良（54.1%）。
- つまり上帯域は「モード判定には効くがルート判定には逆効果」という
  側面があり、合成音源での一方的改善（26.7% → 87.2% 等）は実曲では
  再現しなかった。固定カットオフのまま Phase 1 完了とする根拠は
  この曲からは得られない。
- 次の候補（フェーズ 1.5）: 帯域の使い分け ―― モード（major/minor）
  判定だけ上帯域クロマ、ルート判定は全帯域＋ベース補正、という
  分業構成。あるいは帯域の適応化。本測定の confusion はこの分業で
  両取りできる可能性を示唆する（bass のルート 54.1% と default の
  モード正解率の組み合わせ）。
- コア正解率が全設定 18–26% と低いのは、この曲の正解の大半が
  語彙外（F#m6、Dmaj7、7th 系）で、ルート＋モード両方の一致を
  要求するため。Phase 3 のテンション二段判定のベースラインとして
  この数字を使う。

残り: ユーザーによる正解（特にブリッジと Dmaj7/E の解釈）の確認と、
あと 2 曲の実曲測定。Phase 1 の完了判定はその後。

### TRUTH_NOTES — 正解の構築方法・出典・移調・曖昧さ

コード譜の出典（2 ソース以上の照合が取れたもののみ採用）:

1. **livedoor 詳細コード譜**（作曲者・編曲者クレジット付きの耳コピ譜）。
   冒頭に "key:Db capo1 playC" と明記があり、本文は C 表記
   （カポ1 = 実音より半音低い記譜）、最終サビは C# 表記。
2. **U-FRET 通常 ver.**（data=53559）: ページ自体は実キー D♭ 表記で
   レンダリングされる（イントロの画像コード列 D♭maj7–C7–Fm7–B♭7–
   E♭m7–G♭maj7–B–A–A♭sus4–A♭ が livedoor を +1 したものと一致）。
   検索インデックス側には C 表記の別描画も残っており、これが
   「移調された譜面」の正体だった。
3. **U-FRET 簡単 ver.**（data=65337）: 実キー D♭ 表記で書かれ、
   最終サビは D 表記。詳細譜の骨格確認に使用。
4. **楽器.me 簡易譜**: 実キー D♭ 表記。「エンディングのサビでは
   半音高いキーに転調」と明記。間奏のコード列の出典にもした。
5. **イキスギコード（ChordWiki 系）**: "Key=Db"、Aメロ冒頭を
   D♭add9 – D♭add9/F – G♭M7(9) – F♭ – E♭7sus4(9) – E♭7(9) –
   A♭7(9) – G♭dim と実キーで分析しており、livedoor +1 と一致。
6. 転調の裏付け: 作曲理論サイト sakkyoku.info と ragnet がともに
   「間奏終わりに D♭ → D へ半音転調、転調点は約 5:35」と分析。

**移調の校正（今回の核心）**: 採用した詳細譜（livedoor）は実音より
半音低い C 表記だったため、全イベントを **+1 半音**して実キーに
合わせた（C → D♭、最終サビ C# → D）。校正の検証は音声側でも行った:
(1) パイプライン検出セグメントと低域ベースの循環が D♭ を主音として
整合すること、(2) 転調点で A（D の V）が挿入され D に解決する
ドミナントモーションが検出・整列の双方で約 335 秒に現れること、
(3) イントロ冒頭 4 コード（D♭maj7–C7–Fm7–B♭7）が半小節照合で
そのまま一致すること。なおパイプラインのキー推定は全設定とも
A minor（誤り）で、キー推定自体は校正の根拠に使っていない
（1曲目と同様、相対調・平行調方向への誤判定系）。
テンポはパイプラインが 129（倍取りのオクターブ誤り）と出すが、
グリッド照合では 70 BPM が一貫して最良だったため正解 BPM は 70。

小節グリッドの固定方法:

1. オンセット包絡の自己相関を細密スキャンし、拍周期の候補
   （64.6 / 68.0 / 70.1 BPM）を得た。
2. クロマ新規性＋低域分布新規性の「小節頭への集中度」で候補を
   評価し、**周期 0.856 秒（70.1 BPM）、位相 1.533 秒**を採用
   （集中度 1.56。64.6 は 1.45、68.0 は 1.39）。小節長 3.424 秒 ×
   約 125 小節 ≈ 曲長（無音部含む）。
3. 時刻割り付けはグリッドの半小節（1.712 秒）を量子とし、コード譜の
   イベント列（253 イベント）を半小節集計（全帯域クロマ／上帯域
   クロマ／低域分布）へ DP（動的計画法）で単調整列した
   （イベント長 1–6 半小節、パスコード等のスキップは減点付きで許可）。
   セクション境界はこの整列から決めた。整列の平均スコアは

### conditional の発火分析（この曲の主目的）

Phase 1.5b の残課題は「実曲の分数コードでも崩壊シグネチャが
正しく発火するか」だった。この曲では **発火した（1曲目では 0 件）**:

| 時刻 | hybrid → conditional | 正解 | 判定 |
| --- | --- | --- | --- |
| 21.8–22.2s（0.41s） | D# → G#（表示 G#/D#） | G♭maj7 | 不正解（境界断片、正解境界が内部にある） |
| 26.3–26.7s（0.42s） | G# → C#（表示 C#/G#） | A | 不正解 |
| 27.3–30.4s（3.11s） | G# → Fm（表示 Fm/G#） | A♭ | **不正解（有害）**: hybrid の G#（=A♭）が正解だったものを壊した |
| 333.6–335.1s（1.49s） | A → D（表示 D/A） | E♭m7/A♭（中点） | 境界: 転調境界を跨ぐ。後半は到来する D を先取りしており一概に誤りとは言えないが、正解（中点）基準では不正解 |

- 合計 **4 件・5.43 秒、正解 0 件**（明確な不正解 2 件・3.53 秒、
  境界絡み 2 件・1.90 秒）。指標への影響は hybrid 比で
  ルート −0.7pt／三和音 −1.1pt／コア −0.5pt と小さいが、
  符号は一貫してマイナスだった。
- 有害だった 27.3s の発火は、イントロの A♭ ペダル上でピアノの
  ヴォイシングが F–A♭–C を強調し、上帯域候補 Fm が条件
  （ベース=A♭ が候補の構成音＝短3度、スコア差 ≥0.10）を満たして
  しまったもの。相対短調への引力がスパースなテクスチャで
  誤発火した形で、Song D 型の「強い構成音ベースによる崩壊」とは
  逆向きの誤りである。
- 一方、**本来の分数コード小節では発火しなかった**（次項）。
  D♭/F 型の崩れでは上帯域側も F ルートに崩れていることが多く、
  「上帯域候補が別ルートで明確に勝つ」という条件が成立しない。
  シグネチャは「上帯域が健全な場合の崩壊」しか拾えない、という
  限界が実曲で確認された。

### 暫定所見（Phase 1 完了とは判定しない）

- 1曲目と 2曲目で「効く構成」が逆転した。1曲目は分業
  （hybrid）が全指標最良だったが、この曲では unified 上帯域
  （default / band220）が最良で、分業のモード修正の利得は
  小さかった。病気の内訳が曲ごとに違う（1曲目 = モード反転、
  2曲目 = ドミナントへのルート崩れ）ためで、「どちらの病気が
  実曲一般で支配的か」は 2 曲でもまだ決着しない。
- conditional については、今回初めて実曲で発火し、その発火が
  正解 0 件・有害 1 件だった。発火総量が 5.43 秒と小さく、
  境界断片も含むため断定はしないが、「実曲の分数コードでも
  効く」という仮説はこの曲では支持されなかった。むしろ
  本命の分数小節では無発火で、シグネチャの守備範囲
  （上帯域が健全な崩壊のみ）が実曲の崩れ方と噛み合っていない。
  既定化の最終判断は、少なくともこの所見を踏まえて行うべきで、
  現時点では conditional を既定にする根拠は弱まったと見る。
- 絶対値（最良でもルート 26.0%／コア 14.1%）は、この曲が
  テンション・分数・転調を含む「Phase 0 語彙では最も遠い」
  レパートリーであることの反映であり、Phase 3（テンション
  二段判定＋局所キー）のベースラインとして記録する。
  あわせて、キー推定（全体一括では転調曲を扱えない）と
  テンポの倍取り（129 vs 70）は、帯域戦略とは独立した
  課題として残る。

  と一致したため、bass は実測通り **D** とした。コード名は
  計画通り Fadd9（語彙外。コア判定はルート F＋長三和音コア）。

表記上・解釈上の判断（明示する）:

- **コーダの C/G 交互（78–80 小節）**: C → G → C とした。
  低域は 3 小節とも C が最上位で G は 2 位圏内。交互の開始・
  終端が C である点は低域と整合し、中間を G とする根拠は
  ソース側の「交互」記述に依る（確度は中〜低）。
- **ヴァンプ（81–85 小節）**: 低域が D ペダルでほぼ固定
  （81–83 小節は D 87–100%）される区間を Dsus4／Dm7 の
  交互とし、半小節候補の読み（Dm7 → Dsus4 方向の交代）を
  反映した。ハーネスのコア分解では Dsus4 は「ルートのみ」、
  Dm7 は「ルート＋短三和音コア」として扱われる。84–85 小節は
  フェード末尾（エネルギーは本体の 5% 以下）で判別不能に
  近く、パターンの継続として置いた（低信頼）。
- **低域の C#/D# ブリード**: 本ファイルでは低域ピッチクラス
  分布に C# の系統的な混入（無関係な小節でも 10–60%）が見
  られた。FFT ビン幅（約 10.8Hz）に対し低音域の半音間隔が
  狭いことによる隣接音級への漏れとみられ、ベース関連の
  証拠は本曲では割引いて扱った。パイプラインのベース補正
  自体も同じ入力を使うため、この性質は測定結果側にも
  影響しうる（後述）。

時刻の不確実性:

- グリッド残差は ±0.15 秒程度（位相走査の分解能と F
  ランドマークの合い方から）。感度チェック（後述）:
  正解境界 ±0.3 秒で conditional のルートは −2.3〜+0.4pt、
  三和音は −2.7〜+0.9pt の動きにとどまり順位は不変。
- 追加の整合性チェックとして ±0.87 秒（半小節）シフトも
  測った: conditional のルートは 19.0%／26.8% と無シフト
  （28.1%）より両方向とも悪化した。つまり以下の低調な数字は
  グリッドの半小節ずれでは説明できず、検出そのものの性質。

- 分母の内訳: 三和音は語彙内の正解時間 138.2 秒、コアは

  な三和音曲では全体クロマ推定が機能することの確認になった。
- **BPM: 全設定 92 で、実テンポ約 137 に対し誤り**（比率
  約 3:2）。2曲目の倍取りとは別種の比率取り違えで、テンポ
  推定の課題が残る。
- 支配的な取り違えは全設定共通で「V（D）への崩れ」:
  phase0 で G → D 27.2 秒、C → D 12.1 秒。default では
  G → D 37.4 秒、C → D 19.4 秒とさらに増える。12 弦ギターの
  アルペジオとボーカルが属音側を強く含むテクスチャで、
  テンプレート照合が D に吸われる形。モード誤りは default が
  4.5 秒と最小（上帯域のモード反転抑制はここでも効いている）
  が、ルート崩壊がそれを上回った。
- **上帯域一括（default／band220）がこの曲では最下位側**:
  低域を切ると、残る上帯域は属音・5 度成分が支配的な内容に
  なり、ルートの手がかりがさらに痩せるためとみられる。
  1曲目（上帯域がモード反転を救済）・2曲目（上帯域が最良）と
  並べると、上帯域の効き方はテクスチャ依存であることが
  3 曲で確定した。

  28.1%）。前述の低域ブリードで補正の入力自体が汚れて

### 冒頭和音を何と読んだか

正解セグメント（0.90–3.19 秒、Fadd9／ベース D）に対する
各設定の読みは、全設定共通で **「N.C.（〜1.0 秒）→ Dm」**
だった（default／band220 は Dm が細切れに出るが表示は同じ）。
Fadd9／G7sus4 としての読みはどの設定にも無い。ただし Dm は
この和音の構成音 {D, F, A} をそのまま捉えた読みであり、
実測ベース（D）とも一致する。「語彙外の複合和音を、最も
近い三和音の部分集合で代表した」結果として記録する。
Phase 3 で sus／add9 テンプレートが入れば再評価の対象になる。

### 暫定所見（Phase 1 完了とは判定しない）

- 3曲目の役割は「三和音中心のバンドサウンドでの基準点」
  だったが、結果は基準点どころか全設定で最も低い三和音
  （最良 22.6%）になった。難しさの主因は和声の複雑さでは
  なく、属音を強く含むテクスチャ（12 弦＋ボーカル）への
  テンプレート照合の引力と、低域ブリードによるベース
  証拠の汚れであり、曲の「簡単さ」と検出の「易しさ」が
  一致しないことが分かった。
- 構成間の優劣はこの曲では hybrid（三和音・コア最良タイ、
  ルートは bass と同値）が最も無難で、unified 上帯域が
  最下位側に沈んだ。3 曲を通した既定構成の再検討は
  PHASE1_SUMMARY.md で行う。
- キー推定が初めて当たった一方、BPM は 3:2 の取り違え。
  テンポ推定は 2曲目の倍取りと合わせて、帯域戦略とは
  独立した改善対象として残る。
