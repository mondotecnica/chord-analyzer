## 1. 設計

### 1.1 部品の置き場

新規モジュール `src/analysis/meterEstimate.ts`。局所キー
（localKey.ts）やジャンル傾向（genreProfile.ts）と同じく、
共有プロファイルを読むだけの小さな独立部品として置く:

- 入力: オンセット包絡（混合音。ステム経路では drums ステムの
  包絡を優先 — SUNO_05 の拍子訂正で drums のアクセント周期が
  決め手の一つになったため）、フレーム間隔、第1段の確定
  セグメント境界（コード変化時刻）、検出 BPM、曲長。
- 出力: `AnalysisResult.meterEstimate` への加算的な格納。
  コードラベルには一切触れない（§5 の非目標）。
- 記録／消費の分離（3.3 分割採用と同じ規律）:
  - `meterRecord`: 推定して記録するだけ。結果の `bpm` は
    検出値のまま。
  - `meterArbitrate`: 勝者のテンポスケールを結果の `bpm` に
    反映する「消費」。記録だけの推定は BPM を変えない。
  - 既定値は採用判定で決める（結果は §3: 記録・消費とも
    既定 OFF の明示オプトインとして残した）。

### 1.2 候補と评分（較正後の確定形。経緯は §3 の較正ログ）

検出 BPM は比率取り違え（倍取り・3:2）を含むため、候補は
「テンポスケール × 拍子」の直積とする:

- スケール s ∈ {1/2, 2/3, 1, 3/2, 2}（候補テンポ = 検出 BPM × s、
  40–200 BPM に収まるものだけ）
- 拍子 m ∈ {2, 3, 4, 6}（候補拍周期 = 検出拍周期 / s、
  小節長 L = m × 拍周期。6 は 6/8 として表示する）
- 候補の足切り: 小節長 0.8–10 秒、曲長に対して 3 小節以上。

各候補を4つの証拠で评分する（重み: pulse 0.25 / barSignal
0.5625 / boundary 0.075 / boundaryAc 0.1125。加えてスケール
parsimony として 0.06 × (1 − |log2 s|) を加算する）:

1. **pulse**: オンセット包絡（平均引き＋半波整流、estimateTempo
   と同じ前処理）の自己相関 r を候補拍周期で評価。拍そのものが
   信号に実在するかの証拠。SUNO_05 で棄却された 72 BPM 仮説は
   r(0.833s) ≈ 0 でここで落ちる。
2. **barSignal**: 同じ自己相関を候補小節長 L で評価。小節周期の
   アクセント構造の裏付けであり、小節決定の主証拠。
3. **boundary**: コード変化境界の小節線ヒット率（位相を最適化、
   許容 ±0.15 秒。SUNO_05 検証と同じ流儀）を「超過ヒット率」
   (hitRate − chance) / (1 − chance)（chance = 2·tol/L）に
   変換したもの。ただし部分グリッド（真の小節の 1/2 等）では
   境界が全てヒットして飽和するため、識別力は弱い（補助証拠）。
4. **boundaryAc**: 境界列の自己相関を L で評価。境界を
   ±0.15 秒の三角バンプに広げたインパルス列で測る（幅ゼロでは
   フレーム量子化と境界ジッタで相関が壊れるため）。SUNO_05 の
   stems 検証で「1.667 秒にのみ正のピーク」が観測された系統。
   ただし境界は和声リズムの格子を測るものであり、解析器の
   セグメント分割の癖（小節内の分割）にも左右される（補助証拠）。

评分の細部:

- 自己相関系（pulse / barSignal）は「ゲート付き相対値」で
  スコア化する: clamp(r / 候補中の最大 r) × clamp(最大 r /
  正規化上限)（上限は pulse 0.30 / barSignal 0.20）。絶対水準は
  包絡の性質で大きく変わり、固定上限だけでは密な包絡で全候補が
  飽和して対比が消えるため。最大 r 自体が小さい曲では絶対側の
  ゲートが成分全体を押し下げ、判定保留が効く。
- boundaryAc は clamp(r / 0.30)（実測レンジ: Suno +0.06、
  周期的な境界列で 0.3–0.45）。
- **ラグ精密化**: 自己相関は候補ラグの近傍（±5%、1–3 フレーム）
  の最大を取り、小節長は精密化後の値を境界証拠と出力にも使う。
  検出誤差が数 % あると鋭いピークを外して相関が崩れるため
  （実測: 正解小節でも 2.5% の誤差で r が 0.82 → 0.18）。

### 1.3 勝者の選び方と判定保留（abstention）の規則

選択は二段に分ける（較正で得た中核の設計判断）:

- **小節長は小節レベルの証拠だけで決める**。barSignal＋boundary
  ＋boundaryAc の部分和を正規化した barScore で候補を公称小節長
  のグループ（相対差 1.5% 以内）に分け、グループ順位は barScore
  で決める。pulse を小節決定に入れないのは、信号の最強周期は
  半小節であることが多く（実測: 合成曲では拍ラグの相関がほぼ 0
  で半小節ラグが最大）、入れると 2 倍小節が勝ってしまうため。
- **基本周期の prior**: グループ比較では、小節長が最小候補の
  2 倍になるごとに 0.02 を減点する。周期信号では整数倍の小節長
  でも自己相関がほぼ同等に出るため、「信号を説明できる最短の
  周期が小節」という原則を小さく入れる（証拠差がこれより
  大きい場合は証拠が勝つ）。マージンはこの調整後の差で測る。
- **グループ内では検出器の拍レベルを採用する**。同じ小節長を
  共有する候補（例: 96 の 4 拍子と 48 の 2 拍子）の違いは拍
  レベルの解釈だけで、これはテンポ検出器（60–180 BPM への
  オクターブ補正込み）の領分であるため、スケール 1 に最も近い
  候補を勝者とする。拍レベルの仲裁は小節を跨ぐ場合にのみ起きる。

判定保留の規則: 勝者の総スコアが 0.30 未満、または小節
グループ間のマージンが 0.05 未満、または勝者の pulse の生
自己相関が 0.02 以下なら、拍子は「判定保留」
（beatsPerBar = null）とし、テンポスケールは 1（仲裁なし）
に固定する。誤った自信のある拍子より「不明」が正直である、
という §5 の方針どおり。勝者・次点・各証拠の値は保留時も
記録に残る（診断用）。

## 3. 測定結果

### 3.1 較正ログ（合成曲＋Suno のみで実施。実曲 1–3 は検証専用）

初期設計からの変更は以下の5点。いずれも較正フィクスチャ
（合成 A–I、Suno 両モード）での実測に基づく:

1. **boundaryAc の統計量**: フレーム解像度のインパルス列
   自己相関 → 境界ペアリング率 → **±0.15 秒の三角バンプに
   広げたインパルス列の自己相関**（最終形）。ペアリング率は
   「間隔が真の小節の整数倍でも正」になるため Suno で
   2 小節グループが真の小節と同点に並んだ。広げたインパルス列
   では SUNO_05 検証どおり真の小節にのみ正のピークが出る。
2. **ラグ精密化の追加**: 自己相関は候補ラグ近傍 ±5% の最大を
   取る。検出誤差 2.5% で正解小節の r が 0.82 → 0.18 に
   崩れる実測（Song A）を受けたもの。
3. **勝者選択の二段化**（§1.3）: フラットなスコア比較では
   合成曲の大半が (スケール 1/2, 2 拍子) に倒れた。合成
   フラックスでは拍ラグの相関がほぼ 0 で半小節ラグが最大に
   なるためで、小節長は小節証拠だけで決め、グループ内は
   検出器の拍レベルに従う形に分離した。
4. **重みの再配分**: barScore 内は barSignal 主体
   （総重み barSignal 0.5625 / boundary 0.075 /
   boundaryAc 0.1125）、boundaryAcNorm 0.10 → 0.30、
   基本周期 prior 0.02。境界証拠は和声リズムの格子を測る
   もので、部分グリッドで整列が飽和し（Song C/E/F）、
   解析器の小節内分割があると真の小節に負の自己相関すら
   出した（Song B: 真小節で −0.096）ため補助に回した。
5. 判定保留の閾値（scoreFloor 0.30 / marginMin 0.05 /
   pulseFloor 0.02）は事前登録どおり変更していない。

### 3.3 考察

- **陽性ケース（Suno）と合成曲では設計は機能した**が、実曲の
  ポップ／ロックでは「2 拍レベル」が勝つ。実音源のフラックスは
  バックビートで 2 拍周期が最強になりやすく、解析器のコード
  境界にも半小節の分割が混ざるため、フラックス・境界のどちらも
  4 拍の小節を格上げできなかった。較正フィクスチャは小節
  アクセントが支配的な信号ばかりで、この失敗様式は較正では
  見えなかった（実曲は検証専用の規律どおり較正には使って
  いない。実曲に合わせて定数を動かすことはしない）。
- AHDN ステムの判定保留（margin 0.043）は保留規則が設計
  どおり働いた例だが、混合音では誤って自信を持ってしまった。
- Everything の仲裁失敗は候補生成の構造的な限界: 候補小節は
  検出拍周期の倍数に固定されるため、検出誤差が大きい曲では
  真の小節が候補の近傍にすら入らない。

### 3.4 採用判定（事前登録の規則どおり）

- 記録・表示の既定 ON の条件（C1・C2・C6・C7・C8 の全合格）は
  **満たされなかった**（C1 部分合格、C2・C6 不合格）。
  分割採用（記録だけ既定 ON）も取らない: 失敗しているのは
  消費部ではなく推定そのもの（実曲で誤った拍子が確定する）
  ためで、誤った拍子を既定で書き出しに残す理由がない。
  3.3 の分割採用と違うのはこの点。
- BPM 仲裁の既定 ON の条件（C3・C4・C5）も満たされなかった。
- **結論: 記録・消費とも既定 OFF の明示オプトインとして残す**
  （`meterRecord: true` / `meterArbitrate: true`）。モジュール・
  表示1行・JSON／テキスト書き出しは実装済みで、オプトイン時は
  そのまま使える。アプリの既定動作は従来と完全に同じ
  （C7 で証明済み）。
- 公開（push）は §2 に明記したジャンルモジュールとの分離
  不可の理由により行わず、ローカルコミットまで。

### 3.5 v2 への申し送り

- 小節証拠に「ダウンビートらしさ」を持たせる: ベースステムの
  アクセント周期、和声変化の重み付け（主和音への変化を重く）
  など、2 拍周期と競合できる小節レベルの特徴が要る。
- 仲裁候補の小節長を検出拍周期の倍数から外す（候補小節の
  連続探索）: Everything 型の失敗への対処。
- 位相は境界でなくフラックスのアクセント位相から推定する。
- 実曲の検証曲を増やす場合は、較正用と検証用を分けて
  追加すること（今回の規律の維持）。
