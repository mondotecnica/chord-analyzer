## 結論（先に）

**採用しない（既定への組み込みは見送り）。** 第2段は明示オプション
（`extensions: true`、両経路とも既定 OFF）のまま残す。公開（push）もしない。

理由は事前登録した合格基準3点のうち2点が不合格だったため:

| # | 基準（PHASE3_PLAN.md §3.1） | 結果 |
|---|---|---|
| 1 | Q3 窓（85–93秒）が C → B7 → E7 → Am と読める | **合格**（stems 経路で完全一致） |
| 2 | Q2 窓で Cm を出さない | **不合格**（第1段の Cm が残存。第2段は設計上コアを直せない） |
| 3 | 合成曲・実曲3曲の三和音スコアが記録値を下回らない | **一部不合格**（stems・合成は全て維持／混合音の曲3だけ再解釈の誤発火1件で root −0.3pt・triad −0.4pt） |

一方で、第2段そのものの検出能力は実曲でも確認できた（後述の
givenCore 82–87%）。不合格の主因は「第2段の守備範囲外の問題」
（第1段のモード誤り・進行文脈なしでは決められない maj7）であり、
3.3（局所キー・文脈）の後に再判定するのが筋という結論。

## 作ったもの（Step 0 / Step 1）

### Step 0: 測定基盤
- 拡張音スコアリング scripts/extensionScoring.ts の利用を全スイートに拡張:
  (a) 完全ラベル正解率、(b) コア正解時の 7th 正解率（seventhGivenCore）、
  (c) 誤発火率。既存の root/triad/core 指標は定義不変。
  ※ Song E と measure:seventh は準備段階で既存。本作業で追加したのは
  Song F・実曲／Suno への展開・フィクスチャ。
- Song F（合成・二次ドミナント）: CM7–A7–Dm7–G7 / C–F–G7–Am7（C major）。
  A7 は V/V。三和音小節 C/F は誤発火の対照。
- Suno 05 フィクスチャ（scripts/measurePhase3.ts の evaluateSunoFixtures）:
  Q3 = 2秒スライス×4 の支配ラベル照合、Q2 = 窓内の Cm 系秒数、
  Q1 = 支配的セグメントのベース／ルート保全。

### Step 1: 第2段モジュール src/analysis/extensionDetection.ts
- 第1段の確定セグメントごとに、仮説は最大3つだけ（同ルート maj7 /
  同ルート dom7 または m7 / ♭7 ハイジャック再解釈）。テンプレート
  総当たりはしない。初期語彙は maj7・7・m7 のみ。
- 再解釈は「ベース音が再解釈先ルートと一致」が必須条件。
  キーはソフト prior（ダイアトニック候補のシェア下限 ×0.9）のみ。
- 表現は加算的: ChordSegment.extension（任意フィールド）を新設し、
  表示は fullChordName で合成、JSON 書き出しは extension がある時だけ
  フィールドを足す（後方互換）。N.C. と edited セグメントは対象外、
  信頼度は触らない。

### 設計変更（測定駆動）: 証拠帯域は全帯域 → 上帯域
当初は SUNO_05_ANALYSIS の照合方法に倣い全帯域クロマで設計したが、
調整段階の実測で破綻が判明し、上帯域（chordFrames、第1段のモード
決め直しと同じ帯域）に切り替えた:
- 全帯域ではベース基音（40–60Hz）の半音分解能不足で ±1 半音に滲む。
  Suno の B7 区間では実在しない A# のシェア（0.214）が実在の A
  （0.100）を上回り、maj7 と誤判定した。合成曲でも三和音への
  誤発火が 30% 級（Song B/C）出た。
- 上帯域では合成曲の全小節で分離が明瞭: 真の ♭7 シェア 0.113–0.147
  に対し三和音対照 ≤0.031、真の長7度 0.158–0.172 に対し対照 ≤0.068
  （長3度の3倍音が床を作るため、maj7 の下限だけ 0.10 と高めに置く）。
- しきい値（EXTENSION_CONFIG）はこの実測に基づき合成＋Suno
  フィクスチャで調整し、実曲 1–3 は触らずに検証した。

**Q2（153–168秒）— 不合格（ただし第2段起因ではない）**
- Cm 系の秒数は OFF → ON で不変（stems 4.75秒、混合音 1.10秒）。
  第2段は増やしも減らしもしていない。
- ただし窓内の Cm セグメント1件に m7 が付き **Cm7** になった
  （誤った第1段判定の増幅）。
- 根本原因の分析: 照合時（5秒スライス粒度）では E♭ は全区間で
  E♮ に負けていたが、セグメント粒度では局所的に E♭ > E♮ の
  区間が実在し（165.7–167.3秒、上帯域で 0.204 対 0.094）、
  第1段が Cm と読む。第2段は設計上モードを直せないため、
  この基準は二段判定の枠組みでは合格し得ない。**基準の
  置き場所は第1段のモード判定／3.3 であり、3.1 の基準からは
  外すよう計画側の見直しを提案する**（ユーザー判断待ち）。

**Q1（51–56秒 / 93–98秒）— 部分的**
- ベース D（bassPc=2）とルート（Dm 読み）は両窓とも保全された。
- ただし支配的セグメントに m7 が付き Dm7 になった。実体は
  Am7/D（上層 Am7）であり、C は上層の実在音なので「無根拠な
  発火」ではないが、完全ラベルとしては F を含む Dm7 は
  上層構造の同定として誤り。正しい表現は 3.2 の層表示の仕事。

## 失敗分析

1. **Q2 型（第1段のモード誤りの伝播）**: 第2段は第1段の
   major/minor を信頼する設計のため、モード誤りはそのまま
   拡張音の誤り（Cm7）になる。局所的に「間違った側の3度」が
   実在するケースは、セグメント内証拠だけでは覆せない。
2. **再解釈の誤発火（混合音・曲3、1件）**: 129.2–132.0秒で
   C（ベース D）→ D7。ベース一致＋適合改善のゲートを通過した。
   stems 経路では同種の誤発火ゼロ・真陽性1件だったため、
   混合音特有の証拠の汚さが要因とみられる。影響は −0.3pt 級と
   小さいが、登録基準は「下回らない」であり不合格は不合格。
3. **maj7 の誤発火（ギター主体の三和音曲）**: AHDN stems で
   G → GM7 が 21.4 秒。G の長7度 F# は隣接する D コード等の
   実在エネルギーで、「7th 的な音が鳴っているが和音の構成音
   ではない」ケース。セグメント局所の証拠では原理的に
   区別できず、進行文脈（前後コードで説明できる音は割り引く）
   が要る — 3.3 の局所キー／文脈 prior の守備範囲。
4. **maj7 と dom7 の混同**: 曲1 混合音で Dmaj7 → D7 が 7.9 秒。
   ♭7 と長7度の証拠が拮抗する実音源では fit の差が小さい。
5. **合成曲の半小節ミス**: Song F で CM7／A7／G7 の各1.2秒
   （半小節）ぶん未発火。第1段のセグメント分割位置で証拠が
   薄くなる側の問題。givenCore 72.9% の頭打ち要因。

## 次への提案（ユーザー判断待ち）

- Q2 基準は 3.1 から外し、第1段モード判定の改善課題として
  3.3（局所キー）へ移す。
- maj7 には「隣接コードで説明可能な音の割り引き」という
  文脈 prior を入れてから再判定する（3.3 と同時）。
- その上で 3.1 の採用判定をもう一度回す。第2段の配線
  （オプション・表示・書き出し）は済んでいるため、採用時は
  既定フラグを ON にするだけで製品化できる。
- 語彙拡張（9th/add9）は従来どおり 3.2 と合わせる。
