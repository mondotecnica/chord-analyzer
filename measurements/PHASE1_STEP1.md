# Phase 1 Step 1 測定結果 — ベース解析によるルート補正

測定日: 2026-10-27 / ハーネス: scripts/measurePhase1.ts（`npm run measure:phase1` で再実行可能）

## 実施内容

- `src/dsp/bass.ts`（低域ピッチクラス推定のみに責任を持つ新モジュール）:
  既存 STFT ループ内で、低域（50〜260 Hz）のスペクトルピーク周波数を放物線補間で
  推定し、低域総量をそのピッチクラスへ寄せる（ピーク投票方式）。ビン幅が半音間隔より
  広い低域で、ビン単位の割り当てでは基本波が隣の半音へ漏れる問題への対処。
- `src/analysis/bassCorrection.ts`: セグメント単位で低域分布をエネルギー加重集計し、
  証拠が強い場合のみルートを補正する保守ルール。ベース音は `ChordSegment.bassPc` に
  ルートとは別フィールドで保持し、モードは全帯域クロマから決め直す。
- 分数コード表示と synth のベース音別指定（Step 2）は今回の対象外。

## 使用したしきい値（保守ルール、合成 3 曲で調整した確定値）

- トップシェア下限: 0.5
- マージン（トップ − 2位）下限: 0.2
- 低域エネルギー比率下限（対・曲全体の中央値）: 0.3
- bassPc 記録のみの条件: シェア 0.25 以上、エネルギー比率 0.2 以上

調整時の観測: 正常セグメントではシェア 0.89 以上／マージン 0.77 以上／エネルギー比率
最小 0.40。誤読側（ビン割り当て方式で E→F と誤った区間）はシェア 0.36／マージン 0.10。
しきい値は実測最低値から余裕を取り、誤読側は確実に排除できる位置に置いた。

## 曲別の所見

- Song A: C → Am と誤検出されたセグメントは、低域ピークが C を指す強い証拠
  （シェア 0.98 前後）で両方とも C に戻った。残りの取り違えは境界近傍の
  0.21秒ぶんのみ。残る主な誤りは G → Gm のモード違いで、これは Phase 1 の対象外。
- Song B: C → Am は解消方向。一方でキー誤判定（G major → A minor）はキー推定が
  セグメント列ではなく全体クロマから決まるため、ベース補正では動かない（計画通り対象外）。
  Em 小節内の Dm 誤検出は、低域ピーク補間のおかげで E と正しく読め、Em に補正された。
- Song C: Song B と同様、C → Am の解消と Em → Dm の補正が効いた。G → Gm は残存。
