# 音符レベル解析の狭い統合 — 実装と測定

実施日: 2026-10-29
位置づけ: 音符レベル解析の検証（NOTEPITCH_VERIFICATION.md）で勝ちが
実証された3点だけを、既存の判定構造を壊さずフラグ付き（既定 OFF）で
統合し、事前登録基準で実測する。既定の反転はしない（採用判断は
オーナーが結果を見て行う）。

統合する3点（各々独立フラグ）:

1. **noteBass**: ベース／分数コードのベース確定に音符証拠を使う
   （検証で確立した v2 規則 = 低域音符プールのピッチクラス合算 argmax）。
2. **noteTension**: 第2段拡張判定に、音符の実在証拠を「独立証人」として
   追加する。目的は maj7 誤発火（曲3 G→GM7 21.4秒問題）への独立証拠の
   導入であり、誤発火が増える形は失敗である。
3. **noteBoundaries**: セグメンテーション境界を音符オンセットへ
   近傍スナップする（±0.3秒程度、保守的）。内部の強いオンセットでの
   分割は入れない（スナップのみ）。

基盤として、音符証拠モジュール（src/analysis/noteEvidence.ts）を置く。
モジュール境界は「音符イベント列を受け取る」設計とし、抽出方法
（Basic Pitch 等）には依存させない。ハーネス測定では検証時の音符
キャッシュ（measurements/notepitch/notes/）を読み込んで使う
（製品のブラウザ推論は今回の範囲外）。

## 判定基準（事前登録 — 測定前に固定し、後から動かさない）

- **共通（回帰ガード）**: どのフラグも、既存スイートの主要指標
  （root／triad／完全ラベル）を −1.0pt を超えて悪化させないこと。
  比較は同一ハーネス内の OFF アーム（現行既定パイプライン、
  フレームゲートは現行既定の曲参照ゲート）との差で行う。
- **noteBass**: Song D＋G の完全ラベル平均が OFF 時より +10pt 以上、
  かつ Suno Q1／Q4 のベースが両方正しいこと（Q1: 両窓で支配的
  セグメントの bassPc = D、Q4: 窓 62–65秒で bassPc = C#。
  stems 経路で判定し、混合音経路も併記する）。
- **noteTension**: 曲3 の GM7 誤発火（G の正解区間に GM7 が付いた秒数
  と、maj7 総秒数を併記）が第2段のみの現行（extensions ON・
  noteTension OFF）より減ること、曲1/2 givenCore の低下が −2pt 以内、
  Song E/F 完全ラベル平均が検証時の互角帯域の下限（74.8%）を
  割らないこと。判定は stems 経路を主とし、混合音経路も併記する。
- **noteBoundaries**: 合成スイート（A〜I）完全ラベルの平均が +2pt 以上、
  単曲の悪化が −1pt 以内、実曲 root/triad の悪化が −1pt 以内。
- 判定は統合ごとに独立に行い（分割採用があり得る）、「既定 ON に
  できるか」の提案まで書く。最終決定はオーナー。
- しきい値等の設計パラメータの調整は合成曲と Suno フィクスチャでのみ
  行い、実曲は検証専用とする（従来の測定規律どおり）。

## 設計判断

### 基盤（noteEvidence.ts）

- 型は `NoteEvent { start, end, pitch（MIDI）, amplitude }` と
  `NoteEvidenceInput { harmony, bass? }`。harmony は和声側の音符列
  （混合音経路 = 混合音の音符列、ステム経路 = other の音符列）、
  bass は bass ステムの音符列（ステム経路のみ）。
- 集計は検証時の Python（chordinfer.py）の移植:
  ピッチクラスシェア = 区間と重なる音符の（重なり秒数 × 振幅）合算を
  正規化したもの。ベース v2 = ベースプールの重みをピッチクラス合算し
  argmax。プール上限は検証と同一（混合音 = MIDI 50 以下、
  bass ステム = 60 以下。検証の BASS_POOL_MAX / REAL_BASS_POOL_MAX）。
  TS 移植の正確性は、Suno Q1／Q4 窓で Python の出力と一致することを
  単体テストで確認する（noteEvidence.test.ts）。
- 加えて音符ドメインの持続性として、ピッチクラスごとの被覆率
  （その音が鳴っている時間の割合、区間長で正規化）を証人用に持つ。

### noteBass

現行パイプラインの Song D 混合音を実測して確認した前提:
低域クロマ由来の bassPc は全小節正しく、崩壊しているのはコード
ラベル側（C/E が Em、G/B が Bm と「ベース音ルートのマイナー」へ
潰れる。検出ルート = bassPc のためベース補正は発火できない）。
したがって noteBass は bassPc の付け替えだけでは不十分で、
「分数コードの確定」として次を行う（ベース補正・条件分岐・
モード決め直しの後、層の再読の前に挿入）:

1. 音符ベース証拠が強い（トップシェア ≥ 0.45、マージン ≥ 0.15、
   プール被覆率 ≥ 0.4）場合に限り、bassPc を音符側のトップで置換
   する。bassPc が無い場合は弱い証拠（トップシェア ≥ 0.3、
   被覆率 ≥ 0.3）でも補強として記録する。ゲートの水準は Suno Q1 の
   実測（ベースプールのシェア D 0.378 / G 0.344 と辛勝）を踏まえ、
   「辛勝では置換しない」位置に置いた。
2. 分数確定（ルート書き換え）: 検出ルートが音符ベース音と一致
   （ベースへ潰れた形）し、ベース音を 3rd／5th に持つ別ルートの
   三和音候補が、和声シェアの説明率で現在コードを 0.10 以上上回り、
   かつ候補自身の説明率が 0.70 以上なら、その候補をコードとして
   確定し bassPc をベース音に固定する。正しく読めている
   ルートポジションのコードは現在コードの説明率自体が高いため、
   この差分ゲートが誤発火の主防御になる。
3. 層セグメント（upperChord あり）の扱いは、初回測定のデバッグで
   設計を改めた。当初の「層は触らない」では、Song D の崩壊
   セグメントが全て upperChord を持つため確定対象が丸ごと除外され、
   改善が +4.4pt に留まった。実態は、この段階の upperChord は
   bassCorrection の未精査な仮説（Song D では Dm 等の外れが多い）
   であり、良い上層読みは後の層再読で生まれる。そこで層については:
   (a) 強い音符ベース証拠があり、ベースが一致し、upperChord の
   説明率が現在コードを 0.10 以上上回れば upperChord を本体へ
   「昇格」させる。(b) 昇格が不発でも、検出ルート = ベース音なら
   通常の分数確定（修復）にも落とす。(c) どちらも不発なら層には
   触らない（bassPc の置換・補強もせず、層の再読に委ねる）。
   N.C. と edited は対象外。

### noteTension（証人の使い方）

証人は「7 度音ピッチクラスのシェア証拠の差し替え」として実装する
（ExtensionContext に noteWitness を追加し、judgeExtension の
シェアゲートだけが対象）。理由:

- 課題は maj7 の誤発火を「減らす」ことであり、加算（ボーナス）は
  発火を容易にする方向で目的と逆行する。差し替えなら、クロマでは
  倍音で膨らんだ 7 度音シェア（AHDN の G 区間で床 0.10 を突破）が、
  音符側の実在シェア（ゴースト帯 0.03–0.08）では床に届かず
  ゲートで落ちる。
- 差し替えるのはシェアゲートのみ。持続性と適合度はクロマ側の
  判定を維持し、ダイアトニック緩和・ジャンル係数も床への適用を
  維持する。maj7 の背景シェア割り引き（クロマ固有の補正）は
  差し替え時は適用しない。
- 証人が無い窓（音符が重ならない）ではクロマ証拠にフォール
  バックする。比較のため、加算型（実在証人が強い場合に +0.03 の
  ボーナス）も witnessMode として実装し、測定アームに含める。
- 対象は (a)(b) 同ルート候補のみ。再解釈（c）は従来どおり
  クロマ証拠＋bassPc で判定する（noteBass が bassPc を改善する
  経路とは直交させる）。

### noteBoundaries

- オンセットは harmony＋bass プールの音符開始時刻を 0.05 秒で
  クラスタ化し、強さ = 振幅合計、時刻 = 振幅加重平均、同時発音数を
  持つ。スナップ先は強さ ≥ 1.0 かつ同時発音数 ≥ 2（和音のアタック）
  のクラスタに限る（ベース単音の拍アクセントは境界でない位置にも
  現れるため。合成曲での調整で導入）。
- 内部境界ごとに ±0.3 秒以内の「最近傍」の適格オンセットへ境界を
  寄せる（最強優先は隣接イベントのアクセントに引っ張られるため、
  合成曲での比較を経て最近傍に変更。合成スイートでは両規則の結果は
  一致した）。移動量 0.04 秒未満は動かさない。移動後に両側の
  セグメントが 0.35 秒（SEGMENT_CONFIG.minSegmentDuration）を
  割る場合は動かさない。境界の順序は崩さない。
- 挿入位置は framesToSegments の直後（ベース補正より前）:
  境界汚染は後段すべての集計に効くため、補正として最も上流に
  置く。境界決定そのもの（メディアン／マージ／吸収）は変更しない。

### 配線

- 両経路のオプションに noteEvidence / noteBass / noteTension /
  noteBoundaries（＋測定用の noteTensionMode）を追加。既定は
  全て OFF で、音符入力が無い場合はフラグが ON でも無動作
  （製品のブラウザ推論は範囲外のため、アプリ入口は変更しない）。
- 拡張音検出は extensions 有効時のみ動くため、noteTension は
  extensions と併用した場合にだけ意味を持つ（従来の第2段の
  オプトイン構造を維持）。

### 音符キャッシュの追加抽出

検証時に無かった分を同一手法（Basic Pitch ONNX、抽出スクリプト
共用）で追加した: 曲3 stems（bass/other）、実曲1–3 混合音、
Suno 混合音。混合音はハーネスのデコードと同一条件（44100Hz
モノラル）で WAV 化してから抽出した。

### 機構診断（判定の根拠）

- **noteBass の実曲回帰は「コード書き換え」（修復・昇格）が主因**。
  bassPc の付け替えだけの変更ではコード指標の毀損は観測され
  なかった。混合音では和声プールに旋律線とボーカルが混入し、
  誤った候補の「説明率」が高くなってしまう — 検証で棄却された
  素朴な全音符推論の敗因と同型である。ステム経路でも曲2 の
  root −1.9pt、曲3 の core −11.3pt（語彙外区間の root+mode）の
  悪化があり、書き換えは実音源では正負両方向に大きく振れる。
- **noteTension の敗因は閾値ではなく Basic Pitch の再現率**。
  曲3 のゴースト F# は other ステム音符では全区間 share 0.000
  （クロマ倍音だけの幽霊）だが、曲1 の真の Dmaj7 の C# も大半の
  区間で share 0.000（書き起こしに現れない）。「音符が無い」は
  「音が無い」の証拠にならないため、差し替え型の証人は真の
  maj7 を構造的に否決する。曲1 の損失は Dmaj7 → D（9.7秒）に
  集中していた。逆に言えば、音符が実際に書き起こされている
  区間では証人は正しく働く（曲2 の givenCore は改善）。

## 統合ごとの判定と既定化の提案

### noteBass: 固有基準は合格、共通ガード不合格 → 不採用（再設計）

- 固有基準: Song D+G 完全ラベル平均 +27.3pt（基準 +10pt）、
  Suno Q1/Q4 ベース両方正解 — **合格**。
- 共通回帰ガード: 曲1 混合音 triad −22.7pt、曲2 stems
  root −1.9pt、曲3 stems core −11.3pt — **不合格**。
- 提案: **既定 OFF のまま不採用**。合成分数コードへの効果は
  本物（+54.6pt）だが、実音源での書き換え誤発火が支配的。
  再設計の方向: (1) 書き換えには音符証拠に加えて上帯域クロマの
  適合（層再読の fit）との一致を要求し二重証拠化する、
  (2) 混合音経路ではコード書き換えを行わず bassPc の確定だけに
  限定する、(3) 昇格の説明率床を引き上げ Q4 型の層食いを防ぐ
  （Suno で調整可能な範囲）。bassPc 付け替え単独の製品化は、
  別フラグとして再測定すれば候補になり得る。

### noteTension: GM7 条項は合格、givenCore 条項不合格 → 不採用

- 曲3 GM7 誤発火 21.42 → 0.96 秒（合格）、E/F 平均 77.8%
  （基準 74.8% を維持、合格)、しかし曲1 givenCore −27.4pt
  （基準 −2pt 以内、不合格）。bonus モードは GM7 が減らず
  主条項不合格。
- 提案: **既定 OFF のまま不採用**（第2段自体のオプトイン維持と
  同じ結論）。GM7 への効果は劇的だが、再現率の問題で真の maj7
  と選別できない。再設計の方向: 窓内の音符密度が高い（＝書き
  起こしが十分機能している）場合にのみ証人に棄却権を与える
  「棄権つき証人」、証人プールへのボーカルステム追加の検証。

### noteBoundaries: 実曲条項は合格、合成の平均・最悪条項が未達 → 既定化見送り

- 実曲 root/triad は全曲 −1pt 以内（合格）。しかし合成完全
  ラベルの平均は単独文脈 +0.92pt・拡張文脈 +1.41pt で基準
  +2pt に未達、最悪は単独文脈で Song D −1.8pt（拡張文脈では
  −0.2pt）。**登録基準としては未達**。
- 背景: 検証の「境界汚染が最大 34pt の支配項」は素朴な音符推論
  との比較であり、現行パイプラインの境界（平均オフセット
  0.05–0.36 秒）には +2pt 分の余地が無かった、というのが実測の
  結論である。
- 提案: **既定化は見送り**、オプトインとして残置。3統合の中で
  唯一、実曲・合成の root/triad がほぼ全面で非負で、悪化らしい
  悪化がない。Suno Q1 第1窓の副作用（境界移動が支配的セグメント
  を入れ替える）は申し送りに記録する。本丸はスナップではなく
  検証時の結論どおり「音符オンセット駆動のセグメンテーション
  再設計」であり、そちらは別課題とする。

### 全 ON（all アーム）について

相互作用の参考値: stems では曲1 完全ラベル +9.2pt・曲2 +8.7pt
（noteTension の利得が支配的）、曲3 は −1.7pt。混合音では曲1 が
noteBass の毀損を引き継ぎ triad −20.2pt。全 ON の採用もしない。

## 残課題

- 製品のブラウザ内 Basic Pitch 推論は今回も範囲外。3統合とも
  既定 OFF で出荷コードへの影響はない（フラグ ON かつ音符入力が
  無ければ無動作であることを単体テストで確認済み）。
- noteBass v2（再設計）: 二重証拠化・経路別スコープ・昇格床。
- noteTension v2（再設計）: 棄権つき証人（音符密度ゲート）。
  前提として、実曲 other ステムでの 7th 音の書き起こし再現率を
  先に測るべきである。
- noteBoundaries: オンセット駆動セグメンテーション再設計への
  申し送り（検証の結論と共通）。Suno Q1 型の副作用は再設計時の
  回帰ケースとして使う。
- Suno 混合音の Q1/Q4 ベースは全アーム不変（不正解のまま）:
  混合音経路で音符証拠を成立させるには、ステム推定（簡易分離）
  級の前処理が要る可能性が高い。
