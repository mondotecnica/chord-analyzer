# 音符レベル統合の再試行 — noteBass 分離と noteTension 棄権つき証人

実施日: 2026-10-29
位置づけ: 前ラウンド（NOTEPITCH_INTEGRATION.md）で「固有の勝ちは
大きいが回帰ガードで不合格」となった noteBass / noteTension について、
敗因の機構診断に基づく再設計版を再試行する。既定の反転はしない
（採用判断はオーナーが結果を見て行う）。

前回の判定と敗因（要約）:

- **noteBass**: Song D 完全ラベル 26.7→81.3%、Suno Q1/Q4 ベース正解
  という固有基準は合格。しかし曲1 混合音 triad −22.7pt 等の回帰で
  共通ガード不合格。機構診断で主因は「コード書き換え（修復・昇格）」
  であり、bassPc 付け替え単独では毀損は観測されなかった。
- **noteTension**: 曲3 GM7 誤発火 21.42→0.96 秒と劇的改善も、
  曲1 givenCore 86.5→59.1（−27.4pt）で不合格。敗因は閾値ではなく
  Basic Pitch の再現率: 曲3 のゴースト F# も曲1 の真の C#（Dmaj7）も
  other ステム音符では大半の区間で share 0.000 で、「音符が無い」
  ことが証拠にならなかった。

## 再設計

### noteBass v2: 付け替えの分離

- **基本形（noteBass フラグ）**: 作用を「音符証拠による bassPc の
  確定／付け替え（層表示含む）」に限定する。コードの書き換えは
  一切しない。付け替えのゲート（強い証拠: トップシェア ≥ 0.45、
  マージン ≥ 0.15、被覆率 ≥ 0.4／補強: ≥ 0.3／≥ 0.3）は v1 と同一。
  層セグメントにも付け替えを適用する（v1 は昇格・修復が不発の層を
  無変更としていたが、付け替えはベース確定そのものであり、層再読は
  付け替え後の bassPc を前提に整合させる）。
- **厳格化書き換え（noteBassRewrite サブオプション）**: 修復・昇格は
  独立した経路に分離し、次の全てを満たす場合にだけ許可する。
  1. v1 の音符側条件（強いベース証拠、候補の説明率 ≥ 0.70、
     現在コードへの説明率優位 ≥ 0.10）。
  2. **二重証拠**: 上層証拠クロマ（stems 経路の層再読と同じ
     other 全帯域クロマのセグメント集計）でも、候補の三和音適合度が
     現在コードを 0.06 以上上回ること（層ゲートの分離定数
     LAYER_GATE_CONFIG.minFitGap と同じ水準）。
  3. **stems 経路のみ**（混合音では書き換え禁止。混合音経路で
     noteBassRewrite を指定しても無動作）。
  4. **層の保全**: upperExtension を持つ層セグメントは昇格しない
     （v1 で Suno Q4 の表示が CM7/C# → Em に後退した事故の対策。
     拡張を持つ層は、本体化すると層表示の情報が失われる）。

### noteTension v2: 棄権つき証人

証人は「条件付きでのみ発言する」形に変える。7 度音の不在を反証と
して使えるのは、次の全てを満たす窓に限る（導出根拠は次節）:

- (a) **密度ゲート**: 和声プール（other ステム音符）の書き起こしが
  その窓で機能していること — 窓の和集合被覆率 ≥ 0.75 かつ、
  検出コードの三和音構成音が占める音符シェア合計 ≥ 0.50。
- (b) **不在の二重確認**: 対象の 7 度音ピッチクラスが、混合音プール
  （BP on mix）の音符シェアでも 0.05 未満であること。二重確認用の
  プールが無い経路（混合音経路など）では証人は常に棄権する。

作用の形は2つを測る:

- **veto（主形）**: クロマ判定が通した候補を、証人が発言権を持つ
  窓で 7 度音の音符シェアが 0.02 未満の場合にだけ棄却する。
  追加はしない。
- **gated（比較形）**: v1 の replace（シェア差し替え）を、上記の
  発言権がある窓に限定する。発言権が無い窓ではクロマ証拠に委ねる
  （棄権）。実在（シェア ≥ 0.02）が確認できる窓では差し替えを
  適用するため、v1 で曲2 にあった証人による正しい追加は保持
  され得る。

## 密度規則の導出（診断の実測）

診断: scripts/witness-density-diagnostic.test.ts（第2段のみ vs
replace 証人の2ランを同一第1段で比較し、判定が変わる窓ごとに
候補指標を実測）。生データは witness-density-diagnostic.json。
対象は実曲 stems の拡張が絡む全セグメント（多数決の正解ラベル
による近似分類）と合成 E/F、Suno Q3 窓。

### 密度候補は分離しなかった

誤発火が replace で除去された窓（73.4 秒）と、真の 7th が replace
で失われた窓（14.9 秒）の分布（中央値）:

| 指標 | 誤発火・除去 | 真陽性・喪失 |
|---|---|---|
| 和集合被覆率 | 1.000 | 0.987 |
| 三和音シェア合計 | 0.921 | 0.991 |
| 三和音被覆率（最大） | 0.917 | 0.860 |
| アクティブな音クラス数 | 4 | 3 |
| 音符数／秒 | 11.0 | 4.5 |
| 7 度音の音符シェア | 0.000 | 0.000 |
| 7 度音のクロマシェア | 0.105 | 0.112 |

両集団とも「三和音は書き起こされているが 7 度音だけが欠けている」
窓であり、密度候補（被覆率・三和音シェア・音クラス数）は範囲が
ほぼ完全に重なる。音符数／秒は中央値に差があるものの範囲が重なり、
単独の分離軸にはならない。クロマ側シェアも重なる（0.082–0.167 vs
0.074–0.224）。つまり **other ステムの書き起こし密度だけでは、
「書き起こしが機能していない窓」と「7 度音が実在しない窓」は
区別できない**。曲1 の真の C# は other でも混合音でも書き起こされ
ない窓が実在する（後述）一方、曲3 の窓は三和音が高い被覆率で
書き起こされている。密度ゲート (a) は「証人が語る資格」の最低条件
としてのみ意味を持ち、分離の主軸にはならない。

### 分離の主軸: 不在の二重確認（混合音プール）

判定に直結する2集団での実測:

- 曲3 の GM7 誤発火窓（正解 G、18 セグメント 22.3 秒）: 混合音
  プールでの F# シェアは 20.0 秒分が 0.02 未満、21.8 秒分が
  0.05 未満（残り 0.5 秒だけ 0.238）。閾値 0.05 では棄却の
  **97.8% が維持**される。
- 曲1 の喪失窓（Dmaj7 6 件 11.2 秒＋Bm7 2 件 0.9 秒）: 混合音
  プールに 7 度音が 0.05 以上ある窓は 6.8 秒分（Dmaj7 の
  37.1–40.3 秒 = 0.308、105.0–107.7 秒 = 0.309、155.2–155.7 秒 =
  0.129、Bm7 の 140.2–140.7 秒 = 0.332）で、**喪失の約 56% が
  救済**される。残り約 5.3 秒（Dmaj7 6.0–7.8 秒、200.6–203.3 秒
  等）は混合音プールでも 7 度音が不在で、クロマシェアも
  0.109–0.112 と曲3 のゴースト窓の範囲（0.092–0.130）の内側に
  あり、**現有の証拠源では原理的に区別できない**。

### 導出された規則と予測

規則は前節 (a)(b) の連言とする。閾値: 被覆率 0.75／三和音
シェア 0.50 は両集団の分布の下端を踏まえた「資格」の水準、
混合音シェア 0.05 は 0.02 と同等の救済量で曲3 の維持率が高い
側の値、実在シェアの下限 0.02 は検証時のゴースト帯
（0.03–0.08）の下に置く「明確な不在」の水準。

予測（測定前に記録する）: GM7 条項は合格する（棄却の大部分が
維持される）。曲1 givenCore 条項は、救済が約 56% に留まるため
**不合格の可能性が高い**（−27.4pt の損失の約半分が残る見込み）。
曲2 の条項は、誤発火の除去が二重確認を通過する窓で維持され、
gated 形では正しい追加（A#m7 1.8 秒、GM7 1.0 秒、いずれも密度
ゲートを通過し実在シェアあり）も保持されるため合格圏、
veto 形では追加分を再現できず際どい。E/F は混合音経路で証人が
常に棄権するため ext と一致し合格する。この予測のもとで実測し、
条項ごとに判定する。

## 判定基準（事前登録 — 採用測定の前に固定し、後から動かさない）

### 共通

- **回帰ガード**: どのアームも、既存スイートの主要指標（root／
  triad／完全ラベル／core）を同一ハーネス内の OFF 系アーム
  （noteBass 系は off、noteTension 系は ext）より −1.0pt を超えて
  悪化させないこと。
- **OFF 不変性**: フラグ OFF（および音符入力なし）で全スイートが
  従来値を再現すること。
- しきい値等の調整は合成曲と Suno フィクスチャでのみ行い、
  実曲は検証専用とする（従来の測定規律どおり）。本ラウンドの
  密度規則は上記の診断（前回データ）から導出したものであり、
  採用測定の結果を見てからは動かさない。

### noteBass v2

- 付け替え単独アーム（bassV2）:
  - Suno Q1／Q4 のベース（stems）が両方正しいこと。
  - Suno Q4 の表示が CM7/C# を維持すること。
  - 回帰ガードを満たすこと。
  - 指標の構造に関する注記: ハーネスの「完全ラベル」は
    chord＋extension で決まり bassPc を含まないため、付け替え
    単独では定義上不変である。したがって前回基準の「D+G 完全
    ラベル +10pt」は付け替え単独には構造的に適用できず、
    付け替えの実質は「分数小節のベース正解率・表示一致」と
    Suno フィクスチャで判定する。完全ラベルの改善分は
    書き換え側の寄与として bassV2r で分離して測る
    （これが本ラウンドの分解である）。
- 厳格化書き換えアーム（bassV2r）:
  - 登録の補正（採用測定前に明記する）: 合成スイート（Song D/G）
    は混合音経路で測定され、書き換えは設計上 stems 限定のため、
    合成・混合音では bassV2r ≡ bassV2 が構造的に成り立つ。
    したがって書き換えの改善は stems 系でのみ判定する。これは
    分解の結論の一部でもある: v1 の Song D の勝ち（混合音での
    完全ラベル +54.6pt）は、実混合音で壊滅したのと同じ書き換え
    機構によるものであり、安全な形（stems＋二重証拠）では
    混合音の分数コードには届かない。
  - 実曲 stems で、bassV2 比で主要指標が改善する箇所があり、
    かつ回帰ガードを満たすこと。特に v1 の stems 回帰
    （曲2 root −1.9pt、曲3 core −11.3pt）が解消すること。
  - 曲1 混合音 triad は書き換え禁止により bassV2 と同一
    （構造的不変）であること。
  - Suno stems で Q4 の表示が CM7/C# を維持すること。
    Q1 の支配的セグメントが C に届くかは参考として記録する。
  - 以上を満たす場合のみ「追加採用可」と判定する。

### noteTension v2（主形 veto／比較形 gated を同じ基準で判定）

- 曲3 stems の GM7 誤発火が第2段のみの現行（21.42 秒）から
  50% 以上減少すること（≤ 10.71 秒）。
- 曲1 stems の givenCore 低下が ext 比 −2pt 以内であること
  （ext = 86.5%、前回の replace は 59.1%）。
- 曲2 stems の givenCore／完全ラベルが前回 replace 値
  （82.5%／21.5%）から悪化しないこと。
- Song E/F 完全ラベル平均が 74.8% を割らないこと
  （ext = 77.8%）。
- 回帰ガードを満たすこと。

## 結果

測定: `npm run measure:note-integration`（アーム = off / ext /
bassV2 / bassV2r / tensionV2 / tensionGated）。生データは
notepitch-integration-{synthetic,real-stems,real-mixture,suno}.json。
全テスト 399 件合格＋1 スキップ、ビルド成功。

### OFF 不変性

測定テストの OFF ベースライン検証は合格し、ext アームも v1 の
記録を再現した（曲1 stems givenCore 86.5、曲2 stems 81.0／16.8、
曲3 stems GM7 誤発火 21.42 秒、Song E/F 完全ラベル 81.9／73.7）。
以下、全ての比較はこの土台の上にある。

### noteBass v2（付け替え = bassV2）

- **Suno フィクスチャ（stems）**: Q1 は両窓とも Dm／bassPc 2（D）
  で正解、Q4 は bassPc 1（C#）正解かつ表示 **CM7/C# を維持**。
  フィクスチャ全体（Q3・Q2 含む）が off と一致した。
- **回帰ガード**: 全スイート・全指標で off と完全一致。v1 で
  −22.7pt を出した曲1 混合音 triad も 64.2 で不変。**回帰ゼロ**。
- **合成 Song D/G**: slash 区間のベース正解率（90.1／82.1）と
  表示一致は off と同一で、付け替えの発火箇所は無かった
  （低域クロマ由来の bassPc が既に正しかった）。完全ラベルは
  定義どおり不変（Song D 26.7）。
- **実発火の内訳**（一時診断でセグメント差分を確認）: Suno stems
  144 件中 5 件、実曲1 stems 106 件中 4 件、いずれも bassPc の
  補強（未定義→確定）または訂正のみで、コード変更はゼロ。
  Song D 混合音では発火ゼロ。

**分解の結論**: v1 の見かけの勝ちは2つに分解された。
(1) Song D 完全ラベル +54.6pt は書き換え（混合音）によるもので、
安全な形（付け替えのみ／stems＋二重証拠）では再現しない。
(2) Suno のベース正解は off の時点でも既に成立しており、
付け替えの実寄与は「強い音符証拠がある箇所での bassPc の
独立した確定・補強」である（現フィクスチャでは少数箇所）。

**判定: 登録基準を全て満たし合格。** 既定化の提案: 音符証拠が
利用できる経路で ON にしても実測上の回帰リスクはゼロ。
ただし現フィクスチャでの改善幅も小さいため、既定 ON 化は
オーナーの判断に委ねる（価値は「クロマのベースが誤るケースへの
保険」と、層表示・書き出しに載る bassPc の補強にある）。

### noteBassRewrite（書き換え = bassV2r）

- 実曲 stems: 曲1 は root 61.0→61.5、core 38.1→39.0 と改善。
  曲3 は root 50.7／core 34.7 で、v1 の core −11.3pt 回帰は解消。
  しかし **曲2 は root 27.3→24.7（−2.6pt）、core 20.5→16.9
  （−3.6pt）** と回帰ガード（−1.0pt）に違反し、v1 の stems
  回帰は解消しなかった。二重証拠のクロマ自体が Everything の
  other ステム（漏れの多い録音）では誤候補を支持してしまう
  ＝この録音では音符とクロマは独立な証拠にならない。
- 曲1 混合音 triad は bassV2 と同一（64.2）で、構造的不変は確認。
- **Suno stems: Q4 の表示が Em に後退**（支配的セグメント Em、
  表示 Em）。Q1 は C に到達した（参考条項は達成）。後退の機構:
  書き換えが走る時点では upperExtension はまだ付与されておらず
  （層の再読が後段で付ける）、登録した保護条件「upperExtension
  を持つ層は昇格しない」が作動しなかった。bassCorrection の
  未精査な上層仮説（Em）を昇格が先取りした、v1 と同型の事故
  である。保護を効かせるには「昇格は層再読の後段に置く」順序
  変更が要るが、登録した基準は結果を見て動かさないため、
  本ラウンドでは再調整していない。

**判定: 不合格（追加採用不可）。** 理由は曲2 stems のガード
違反と Q4 表示条項の違反の2点。フラグ OFF のオプトインとして
残置する。再挑戦の条件は、順序変更（層再読の後）＋漏れ stems
でのクロマ証拠の信頼度条件の追加である。

実曲 stems（ext を基準。givenCore／完全ラベルは %、GM7 は秒）:

| 1 | givenCore | 86.5 | 70.9 | 79.1 | ≥ 84.5 ✗ 両形 |
| 1 | 完全ラベル | 56.7 | 56.8 | 58.4 | （参考） |
| 2 | givenCore | 81.0 | 81.3 | **82.6** | ≥ 82.5: veto ✗ / gated ✓ |

- **GM7 条項は両形とも合格**（21.42→1.41 秒、−93%。v1 replace
  の 0.96 秒に近い水準を、棄権つきで達成）。
- **曲1 givenCore 条項は両形とも未達**。ただし v1 replace の
  −27.4pt からは大きく回復した（veto −15.6pt、gated −7.4pt）。
  事前登録の予測どおりであり、残存損失は診断で特定した
  「混合音プールでも 7 度音が書き起こされない真陽性窓」
  （Dmaj7 の一部など）に対応する。**現有の証拠源（other 転写＋
  混合音転写＋クロマ）では、この窓とゴースト窓は原理的に
  分離不能**という結論を、本測定が裏付けた。

- **E/F 条項は両形とも合格**（77.8 = ext と一致。混合音経路で

- **回帰ガード**: veto は全スイートで ext と同等以上（混合音

- Suno stems: veto は Q3 全合格・Q4 表示 CM7/C# 維持（ext と
  一致）。gated は Q3 の E スライスが E7→E に落ちた（登録条項
  外だが記録する）。

**判定: 両形とも不合格**（曲1・曲2 条項）。ただし GM7 誤発火の
劇的削減と、曲2／曲3 stems の完全ラベルの大幅改善
（+3.0〜+19.9pt）は実在し、代償は曲1 の真の maj7 の一部喪失
という明確なトレードオフである。既定化の提案: 今回は反転
しない。残すなら gated 形を「stems 経路＋第2段 ON のときの
証人」としてオプトイン残置するのが最も実態に近い。

### 残課題

1. 書き換えの再挑戦には、適用順序の変更（層再読の後段）と、
   漏れの多い stems でクロマ証拠を割り引く信頼度条件が要る。
2. noteTension の残存損失は転写（Basic Pitch）の再現率の問題
   であり、閾値や規則の調整では解けない。解くなら証拠源の
   追加（ベース／メロディ帯の持続性証拠、転写モデル自体の
   改善）が要る。
3. ブラウザでの Basic Pitch 推論の実測（速度・メモリ）は
   依然未実施で、製品組み込みの前提として残る。
4. オンセット駆動の再セグメンテーション（検証ラウンドの
   本丸）は別課題のまま。
