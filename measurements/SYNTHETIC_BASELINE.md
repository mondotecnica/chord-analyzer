# 合成テスト音源ベースライン測定 — Phase 0

測定日: 2026-10-27 / ハーネス: scripts/measureSynthetic.ts（`npm run measure:synthetic` で再実行可能）

## 注意（先に読むこと）

- これは**クリーンな合成音源**での測定であり、達成可能な上限に近い「ベストケースの土台」である。
  実楽曲（ドラム、ボーカル、リバーブ、テンションコード等）はこれより確実に悪くなる。
  **この数字を実楽曲の正解率として読んではいけない。**
- 目的は、実曲測定の前に「測る仕組み自体が回ること」と「素の三和音進行での上限」を確認すること。
- 合成音源は test-audio/ に WAV と正解 JSON が保存してあり、プレビュー版にそのまま入れて手動確認もできる。

## 測定方法（ACCURACY_MEASUREMENT.md 準拠）

- 検出セグメントと正解セグメントを 10ms 刻みで時刻軸突き合わせし、時間加重で集計。
- ルート正解率・三和音正解率は、N.C.（無判定）区間の時間を分母から除外し、N.C. の割合は別掲する。
  参考として N.C. も不正解に数えた全時間ベースの値も併記する。
- 「コア正解」（テンション曲向け別枠）は、今回の3曲が全て Phase 0 の語彙内
  （major/minor 三和音のみ）で構成されているため、三和音正解率と同一になる。別枠の対象曲はない。
- キーは全体推定（Krumhansl–Schmuckler）、BPM はオンセット自己相関の推定値と正解を比較。

## 考察（誤りパターンの内訳）

判定対象時間（N.C. 除外）のうち、ルートは合っているのに major/minor が違う時間は 約 4.8秒（9.0%）、ルート自体が違う時間は約 7.4秒（14.0%）。

全曲通算の主な取り違え:
- G → Gm: 3.66秒
- C → Am: 3.32秒
- Em → Dm: 1.86秒
- D → Dm: 1.10秒
- G → Am: 0.77秒

読み取れる傾向:
- 誤りは大きく2クラス。ルート自体の誤り（約14%）が最大で、その中心は C → Am のような
  相対調（構成音が2つ重なる）コード同士の取り違え。これはベース音（Phase 1）で最も素直に解ける種類。
- もう一方は「ルート正解・3rd 誤り」（約9%、ルート正解率と三和音正解率の差そのもの）で、
  単一ペア最大の G → Gm をはじめ major → minor 化に偏っている。合成音の倍音成分や
  前コードの減衰テールが短3度側のクロマを押し上げている可能性があり、Phase 1/3 で
  3rd 判定をどう安定させるかが論点になる。
- Em → Dm のような全音違いのルート誤りも見られた（境界近傍に集中しているかは曲別一覧参照）。
- キー推定は Song B — G major (I–ii–vi–IV / I–ii–IV–V) で外した（正解 G major → 検出 A minor）。相対調・近親調のコードが長く続く進行では、全体集計クロマがそちらに寄る。
- 境界ずれの平均は 0.08〜0.17秒程度で、セグメントの切替自体は概ね小節に追随している。

次の一手への含意（ACCURACY_MEASUREMENT.md の分岐に従う）:
- ルート誤りの中心が相対調の取り違えである点は、Phase 1（ベース補正）を優先する
  当初計画と整合する。ベースでルートが固定されれば、このクラスは直接減らせるはず。
- 3rd 誤り（major → minor 化）も無視できない規模なので、Phase 3 の二段判定
  （コア確定→拡張音検出）の設計では「major/minor 判定の安定化」を意識したい。
- 最終的な優先順位の結論は、実曲3曲の測定結果と合わせて出すのがよい。
