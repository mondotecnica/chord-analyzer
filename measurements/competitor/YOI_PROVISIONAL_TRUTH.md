## B–E カデンツの解釈（2026-10-31、作り手判断による追記）

初練習後の回答で、作り手は B–E の流れについて次のように判断した:
「基本的には Bm7–Em7 だと思いますが、時々 Gmaj9/B–E7 のような
流れになることもあります」。個別フィクスチャの記述は変更せず、
解釈の層として以下を追記する。

- **基本形は Bm7–Em7**（コード譜側の書法）である、という作り手の
  判断として記録する
- ただし**変種として Gmaj9/B–E7 のような流れになる出現もある**。
  したがって信号／ツール側の B7／E7 読みは一律に「誤読」とは
  断じず、**変種の出現を捉えた可能性**として再解釈する。B の上で
  E♭（= D♯）が鳴るモチーフが B7 的な読みを生む経路は、Q2 の調査
  （128 秒・141 秒の E♭ は B の長 3 度として機能）にも記録がある
- 評価上の含意: このカデンツは定型としてではなく**出現ごと**に
  照合する。「信号は B7／E7、譜面は Bm7／Em7」というクオリティ
  対立は、未決着の対立としては扱わず、**基本形＋変種**として
  決着とする
- 上記の再解釈は留保でもある: 「92・93 小節の D→E7 は繰り返し
  部分で Bm7→Em7 と読まれるため誤読の可能性が高い」という既存
  判断は、初出と繰り返しの並行性を根拠にしていた。しかし出現
  ごとに変種がありうる以上、初出が繰り返しと違うこと自体は
  誤読の証拠にならない。フィクスチャ記述（92・93 小節 = D→E7
  という書き起こし事実、繰り返しが 100・101 小節 = Bm7→Em7
  という事実）はそのままに、この論法は弱まったものとして扱う
- 観察: **Gmaj9/B は 76 小節の耳決着であるだけでなく、カデンツ
  の変種としても現れる**（コード譜のサビ L2 のトークン列そのもの
  が Gmaj9/B–E7 である）。B をベースにする地点で共通して使われる
  色彩装置である可能性があるが、現時点では観察に留め、断定しない

  デフォルトが C で、うっかりそのままだったから見落としていた
  だけ」と訂正した。ヘッダの Key: C は作り手の意図的なキー指定
  ではなく、**証拠価値はない**。よって本提案は、ヘッダを根拠と
  しない形に改める
- キー論点は訂正前の状態に戻す: ユーザーの認識は C
  （2026-10-28、競合比較以前からの本人の認識）、Chord AI の
  読みも C、自アプリは Am 寄り（信号側は A minor が僅差で先行
  という従来の測定）、で**未確定**。本書にはこの状態そのものを
  記録し、どちらかで他方を上書きしない

### 提案 2: コード譜の語彙は「作り手の表記」として併記し、決着ラベルは置き換えない

- **Gmaj9/B（サビ、76 小節）**: 耳決着は **Gmaj7/B** のまま維持する。
  コード譜の 9th（A）については、2026-10-31 に作り手が「音源に
  含まれている」と判断した（根拠は音高の直接同定ではなく、音源の
  くぐもりという音色面の判断。§2 の 9th の項参照）。ただし A は
  Bm9 の構成音でもあるため判別子にはならず、決着ラベルは変更
  しない。「コード譜は Gmaj9/B と表記（δ 配置では当該位置の譜面
  トークンは Bm9）」という併記に留める
- **C#m7(b5)（Bメロ、Q4 範囲内）**: Q4 の決着（上層 CM7＋ベース C#、
  層表記 CM7/C#）は置き換えない。コード譜の C#m7(b5) {C#, E, G, B}
  は決着した上層と E・G・B を共有し、検証済みベース C# をルートに
  取る**作り手言語での別レンダリング**として注記することを提案する
- **Cm7（サビ2 L1、サビ末尾行）**: イベントの検証内容は
  C–E♭–G 三和音であり 7th（B♭）は含まれないこと、暫定正解では
  色彩イベント層（進行は C）に置く一方でコード譜は進行層に Cm7 と
  書くことは、**層の置き方の違い**として注記するに留める。
  色彩イベントの分類そのものは変更しない

### 提案 3: 取り込まないもの（明示）

- 対応付けが「中」以下の箇所（イントロの G/F・Gadd9、Bメロ L3 の G、
