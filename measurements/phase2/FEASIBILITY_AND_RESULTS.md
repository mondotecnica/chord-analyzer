## Stage 2 判定: この環境で HTDemucs 分離は「可能」

### 環境と導入経路

- 環境: Python 3.12.3 / CPU 2 コア / RAM 7.7GB（スワップなし）/
  ディスク空き 149GB / Node v24。
- 導入: venv（tools/phase2-venv）に torch 2.14.1+cpu /
  torchaudio 2.11.0+cpu（PyTorch CPU インデックス）と
  demucs 4.1.0 を pip 導入。アプリのソースツリーには混入させていない。
- モデル: HTDemucs（adefossez/HTDemucs、safetensors 84MB）。

### つまずきと対処（再現時の注意）

1. download.pytorch.org への初回接続がタイムアウト
   → pip の --timeout 300 / --retries 10 で解決。
2. demucs 標準の HF ダウンロードが 0 バイトで停滞
   → 原因は hf-xet 転送経路。環境変数 HF_HUB_DISABLE_XET=1 で
   通常 HTTPS に落とすと即座に取得完了した。
   なお demucs の --repo（ローカルモデル）は .th 形式専用で、
   safetensors の現行モデルには使えないことも確認した。
   取得済みファイルは tools/htdemucs-repo/ にも curl で複製してある。
3. 分離の実行自体は上記以外の問題なし。

### 分離品質の sanity

- 曲1: ステム別 RMS（混合音比）drums 0.30 / bass 0.43 /
  other 0.22 / vocals 0.35 と各ステムに実質的なエネルギーが乗り、
  bass ステムの低域分布トップシェア中央値は 0.66（混合音 0.47）
  と、ベース証拠が混合音より鋭くなった。
- 曲3: bass ステムの RMS が混合音比 **0.01** しかない。
  1964 年録音（モノラル寄りミックス）ではベースが bass ステムに
  ほとんど分離されず、大部分が other 側に残ったとみられる
  （トップシェアも 0.38 と混合音の 0.50 を下回る）。
  「古い録音では bass ステムを盲信できない」という前提が要る。
  それでも曲3 の精度は大きく改善した（下記）ため、改善の主因は
  bass ステムではなくボーカル除去の側にあると解釈する。
- 曲2: ステム別 RMS（混合音比）drums 0.19 / bass 0.27 /
  other 0.32 / vocals 0.49。bass ステムの低域分布トップシェア
  中央値は 0.57（混合音 0.49）と、曲1 同様にベース証拠は
  混合音より鋭くなった。ただし分数小節の改善には直結しなかった
  （仮説 3 参照）。分離時のピーク RSS は 2,636 MB と過去 2 曲
  （約 1.6 GB）より大きく、長尺曲ではメモリ見積もりを
  引き上げる必要がある。
- Song D（合成）: drums / vocals の RMS は 0.00 で、bass 0.79 /
  other 0.60 とほぼ理想的に分離された（トップシェア 0.99）。
  合成音は Demucs の学習分布の外にあるはずだが、この素材では
  分離はほぼオラクル条件になった。Song D の stems 数値は
  「分離が理想的なら届く上限」の証拠として読むべきで、
  実曲での期待値ではない。

## Stage 3 結果: stems 設定 vs 現在の既定（hybrid、混合音）

構成（再掲）: コード判定クロマ = other ステム全帯域、
ベース補正の低域分布 = bass ステム、モード決め直し = other
ステムの上帯域（既定 split の適応）。キー／テンポは混合音。
同一実行で測った混合音・既定の数値は Phase 1 の記録値と
完全一致し（曲1: 54.1/64.2/31.1、曲2: 22.7/31.6/13.9、
曲3: 28.1/22.6/36.0、Song D split: ルート 26.7%）、
比較の物差しが揃っていることを確認した。

感度（正解境界 ±0.3 秒）: 曲1 は順位不変（ルート 58.1–61.0%）。
曲3 は -0.3 秒側で stems のルートが 45.2% まで下がるが、
それでも混合音既定（28.1%）を大きく上回る。

19.4–21.7% で、hybrid（22.7/31.6/13.9）との順位は全シフトで
不変。ただしルートは unified260 の無シフト値（25.9%）と
-0.3 秒側で重なる範囲にあり、ルートの優位は小さい。
コアは全シフトで stems が両混合音設定を上回る。

### 仮説への回答（PHASE2_PLAN.md §4）

1. **曲1 のモード反転は消えるか → ほぼ消えた。**
   三和音 64.2% → 81.7%（+17.5pt）。other ステムのクロマで
   判定することで、低域倍音・ボーカルの混入が入力段階で
   断たれた。ルートも 54.1% → 61.0% と改善。
   残る最大の誤りは F#m6 → A（12.3 秒、相対調方向）と
   Dmaj7 → E（11.5 秒）。後者は Phase 1 から記録してきた
   「Dmaj7/E は E ルートのドミナント（E9/E13）とも解釈できる」
   という正解側の曖昧さそのもので、ベース音 E を根拠に E と
   読むのは音楽的には筋が通っている。正解の符号化を E に
   変えればルートはさらに上がるが、ここでは変えていない。
2. **曲3 の属音引力は緩むか → 大きく緩んだ。**
   G → D は 6.8 秒（Phase 0 の 27.2 秒、hybrid でも支配的
   だった誤り）。ボーカル（RMS 比 0.48 と最大のステム）を
   除いたことが効いたとみられる。ルート 28.1% → 50.6%、
   三和音 22.6% → 51.7%。代償として G → C（IV への引力）
   13.5 秒が新たな最大誤りになり、コアは 36.0% → 34.7% と
   微減（感度の範囲内）。「V への吸着」が消えた代わりに
   「I と IV の取り違え」が残った形で、次の課題はここ。
3. **曲2 の分数小節は bass ステムで改善するか → ほぼ改善しなかった。**
   分数コード 33 区間（約 60 秒）の時間加重では、stems は
   ルート 25.7%（混合音 hybrid 24.0%、+1.7pt）、ベース一致
   50.6%（同 48.4%、+2.2pt）と僅かに良い一方、分数として
   完全正解は 6.5% と混合音（8.2%）を下回った。bass ステムの
   証拠は混合音より鋭くなった（トップシェア 0.57 vs 0.49）
   のに分数の読みは解けていない。実曲の分数小節のボトルネックは
   ベース証拠の鮮明さだけではなく、ペダル／3 度ベース上で
   other ステムのクロマ自体がルートを取り違えること
   （E♭m7/A♭ 型のペダル誤読など）にあるとみられる。
   一方で曲2 全体では stems が効いた: コア 13.9% → 20.7%
   （unified260 の 14.1% も上回る）、ルート 22.7% → 27.1%。
   V への引力は弱まったが消えてはいない（D♭ → A♭ は
   13.0 秒 → 9.6 秒）。代わりに E♭7 → D♭、E♭m7 → D♭
   （計約 15.7 秒）という「I のルートへの吸着」が新たな
   誤り型として出た。テンション主体の曲では、ボーカルと
   ドラムを除いた other クロマがコアの読みを素直にする、
   というのが曲2 での stems の効き方だった。
   なお曲1 の分数区間（Dmaj7/E の 11 区間）では、stems は
   ベース一致が 65.1%（混合音 50.3%）に上がる一方、ルートは
   15.1%（同 35.6%）に下がった。これは stems が当該小節を
   E と読むためで、仮説 1 で触れた正解側の曖昧さ
   （Dmaj7/E か E9/E13 か）そのものである。ベース音 E の
   検出自体は stems でむしろ正確になっている。
4. **Song D のルート崩壊は bass ステムで解けるか → 解けた。**
   stems のルートは **98.6%** で、混合音 split の 26.7% は
   もちろん、上帯域一括（unified260）の 87.2% も上回った。
   分数として完全正解も 98.4%（混合音 split 26.6%）。
   フレーム判定の入力からベース基本波が物理的に除かれれば、
   上帯域カットのような対症療法なしに崩壊そのものが
   起きない、という機構の証明になった。ただし前記の通り
   合成音では分離がほぼ理想条件になっており、この数値は
   上限の証拠であって実曲の期待値ではない。実曲側の対応物
   （仮説 3）が解けていないこととセットで読む必要がある。
5. 副作用（N.C.）: 実曲 3 曲のうち 2 曲で増えた
   （曲1: 3.4% → 6.9%、曲2: 0.3% → 1.9%、曲3: 1.6% → 1.1%
   と微減）。other ステムは間奏などでエネルギーが細り、
   フレームエネルギーの閾値に触れやすい。製品化時は
   N.C. 判定のエネルギー基準をステム入力向けに見直す
   余地がある、という所見は全素材を通して維持される。

### 全素材を通した総括

- **ステムが効く病気**: モード反転（曲1 でほぼ解消）、
  属音への引力（曲2・曲3 で軽減）、テンション主体の曲の
  コア読み（曲2 で +6.8pt）、合成分数コードのフレーム崩壊
  （Song D で機構を証明）。実曲 3 曲すべてでルートは
  混合音既定を上回った（61.0 / 27.1 / 50.6 vs
  54.1 / 22.7 / 28.1）。
- **ステムでも解けない病気**: 実曲の分数コード（曲2 の
  分数小節は横ばい〜微減）。ペダル／ヴォイシング由来の
  ルート取り違えは other クロマの中に残る。キー推定の誤り
  （曲1・曲2 の A minor）と BPM の比率取り違えは、
  キー／テンポを混合音から取る現構成では当然ながら不変で、
  計画通り Phase 3 の課題。
- **前提の留保**: 古い録音では bass ステムがほぼ空になる
  （曲3、RMS 比 0.01）。曲3 の改善主因は bass ではなく
  ボーカル除去であり、「bass ステムの証拠で治す」という
  描像は録音の年代・ミックスに強く依存する。bass ステムは
  鮮明さ（トップシェア）を見て信頼度を落とせる設計が要る。
- **副作用**: N.C. の増加（実曲 2/3 曲）。ステム入力向けの
  エネルギー基準の見直しが製品化の前提作業になる。
